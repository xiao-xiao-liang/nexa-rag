# 文档任务与可靠投递术语表

| 名称 | 含义 | 所有者 | 非含义 |
| --- | --- | --- | --- |
| 文档任务（Document Task） | 一次可追踪的文档业务操作，例如处理、索引清理或告警投递。 | `document_task` | 不是一条 MQ 消息，也不等同于一次发布尝试。 |
| 任务执行版本（Operation ID） | 同一文档任务的一次业务执行实例；人工重跑产生新版本。 | 文档任务 | 不是 RocketMQ 消息 ID。 |
| 进行中处理任务 | 同一文档当前尚未进入终态的 `PROCESS_DOCUMENT` 任务。新处理请求必须被拒绝，直到该任务进入终态。 | 文档任务 | 不表示可以用新操作版本覆盖旧任务。 |
| Outbox 消息 | 为可靠投递而持久化的一条消息记录，可关联一个任务。 | `document_task_outbox` | 不是任务的唯一身份，也不表达任务是否执行成功。 |
| 发布租约（Claim） | Publisher 在有限时间内获得发送某条 Outbox 的权利。 | Outbox | 不是消费者执行租约。 |
| 投递最终失败 | Outbox 已达到最大发布尝试次数但未获 MQ 确认的终态。关联任务必须进入失败处理，而不是长期停留在排队中。 | Outbox 与文档任务 | 不等同于消费者执行失败，但两者共用告警和人工补偿入口。 |
| 执行租约（Execution） | Consumer 在有限时间内获得执行某个任务的权利。 | 文档任务 | 不是消息是否已经投递到 MQ 的证明。 |
| 幂等键 | 用于确保重复投递或重试不会重复产生业务副作用的稳定业务标识。 | 数据库约束与消费者 | 不能只依赖 Redis 的短期键。 |
| At-Least-Once 幂等 | 同一 `taskId` 可能被多次交付或在租约交接后再次执行，但最终业务效果只能发生一次。 | 每个任务处理器 | 不是 MQ 或 Redis 自动提供的 Exactly-Once。 |
| Redis 调度加速 | 对已提交 Outbox 的就绪通知、延迟唤醒、限流或热点去重。 | Redis | 不保存最终任务状态，也不替代数据库对账。 |
| 首期数据库闭环 | 不依赖 Redis 的任务可靠性实现：数据库调度、条件租约、MQ 投递、消费者幂等与对账恢复。 | 文档任务模块 | 不表示未来禁止引入 Redis 加速。 |
| 对账扫描 | 从数据库发现未被 Redis/MQ 正常唤醒的待处理记录并恢复推进。 | Publisher/调度器 | 不是主业务逻辑的唯一触发方式。 |
| 任务归档 | 将进入终态超过 30 天的任务及其终态 Outbox 从在线工作集迁出，同时保留可审计、可查询的历史。 | 文档任务模块 | 不是直接物理删除，也不得影响进行中任务的调度。 |
