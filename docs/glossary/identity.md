# 身份与认证术语表

| 名称 | 含义 | 所有者 | 非含义 |
| --- | --- | --- | --- |
| 账号（Account） | NexaRAG 中承载业务数据归属与登录主体的持久化身份，标识为 `accountId`。 | 身份领域 | 不是某一种登录凭据，也不等同于第三方平台的用户。 |
| 用户（User） | NexaRAG 中不可变的业务用户与业务数据所有者，标识为 `userId`；一期与一个账号严格一对一。 | 用户领域 | 不是账号名、邮箱地址或第三方平台主体 ID。 |
| 用户与账号一对一 | 一期每个 `userId` 恰有一个 `accountId`，每个 `accountId` 也恰属于一个 `userId`；认证成功后两者均可由服务端可靠解析。 | 身份领域 | 不是允许一个人通过多个账号访问同一用户数据，也不是把 `user_id` 改作账号名。 |
| 账号 ID（accountId） | 不可变的登录账号主体标识，用于关联账号名、状态、邮箱、密码、第三方身份和角色。 | 账号领域 | 不是用户 ID，也不是允许改名后变化的账号名。 |
| 用户 ID（userId） | 不可变的业务用户标识，用于现有聊天等业务数据的所有权与范围校验。 | 用户领域 | 不是账号 ID、可变账号名或前端可指定的请求参数。 |
| 账号状态 | 账号生命周期的统一开关；一期仅有 `ACTIVE` 与 `DISABLED`。禁用状态会撤销全部会话并拒绝所有认证入口；受控运维重新启用后也不恢复旧会话。 | 账号安全领域 | 不是删除某一个密码、邮箱或第三方身份，也不是前端隐藏某个功能入口。 |
| 租户（Tenant） | 组织或工作空间级的数据与访问隔离边界，标识为 `tenantId`；可包含多个账号以及共享的知识库、文档等资源。 | 租户领域 | 不是单个账号、账号名或某一种登录凭据。 |
| 租户主数据 | 持久化保存企业/工作空间租户身份、名称、状态与审计信息的租户表记录。 | 租户领域 | 不是在应用配置中临时约定的字符串，也不等同于租户成员关系。 |
| 租户成员资格 | 不可变 `userId` 与 `tenantId` 之间的持久化访问关系；创建企业租户的管理员自动成为其唯一初始所有者。 | 租户领域 | 不是全局 `ADMIN` / `USER` 角色，也不是客户端传来的当前租户参数。 |
| 租户所有者 | 企业租户创建时自动建立的首个成员资格，具有该企业空间的所有者语义。 | 租户领域 | 不是任一默认租户用户，也不自动等同于全局 `ADMIN` 角色。 |
| 租户内角色 | 成员资格上的 `OWNER` 或 `MEMBER`：前者治理成员，后者使用租户业务数据；不影响全局模型管理权限。 | 租户领域 | 不是 `auth_role` 中的全局 `ADMIN` / `USER` 角色。 |
| 租户所有者转交 | 当前 `OWNER` 经最近验证发起、接收成员登录后明确接受才生效的敏感操作；生效后原所有者降为 `MEMBER`。 | 租户领域 | 不是全局 `ADMIN` 角色授予，也不是将租户资源转移到另一个 tenantId。 |
| 租户邀请 | 租户所有者向现有用户发出的加入企业租户请求；受邀用户在登录状态下明确接受后，才建立成员资格。 | 租户领域 | 不是直接授权、公开注册链接或任意用户的自助申请。 |
| 租户成员管理 | 租户所有者撤销未接受邀请或解除普通成员有效成员资格的操作；成员解除后适用租户失效回退。 | 租户领域 | 不是撤销成员的账号、全局角色或其他租户资格。 |
| 退出企业租户 | 普通成员主动解除自身企业租户成员资格的操作；立即失去该租户访问权并回退默认租户。 | 租户领域 | 不是删除用户账号；唯一租户所有者不得通过此操作留下无所有者租户。 |
| 当前租户 | 当前 Sa-Token 会话在服务端保存的唯一工作空间 `tenantId`；新登录默认指向默认租户，切换时必须校验成员资格。 | 会话与租户边界 | 不是每次请求由前端任意传入的 tenantId，也不是另一份登录身份。 |
| 租户失效回退 | 当前企业租户的成员资格被移除或租户被禁用后，服务端立即拒绝该租户访问，并在下一请求把受影响会话切回默认租户。 | 会话与租户边界 | 不是撤销账号全部登录态，也不保留旧租户的访问窗口。 |
| 默认租户归属 | 一期中新建账号在创建时自动加入系统内建默认租户，当前请求的租户由服务端从账号归属确定。 | 身份与租户边界 | 不是客户端可任意传入或切换的 tenantId。 |
| 最小角色授权 | 一期中服务端以固定 `ADMIN` 与 `USER` 角色区分高风险运维能力；普通业务数据仍按主体归属与租户边界约束。 | 授权领域 | 不是由前端菜单决定的可绕过控制，也不是一期完整的可配置 RBAC。 |
| 管理员（ADMIN） | 可访问模型网关裸 Chat 与提示词管理接口的受控角色；默认管理员账号承接固定开发用户的既有业务数据。 | 授权领域 | 不是任一已登录用户，也不是通过账号名、首个注册或客户端参数自动取得的权限。 |
| 管理员角色非委派 | 一期只有部署初始化的默认管理员具备 `ADMIN`，不提供对其他用户授予、转让或撤销管理员角色的 API、界面或普通运维入口。 | 授权领域 | 不是允许管理员在业务系统内自行培养更多管理员。 |
| 模型管理员边界 | `/api/model/**` 下的全部接口只允许 `ADMIN`，包括模型调用、提示词、模型与供应商配置、路由及治理配置。 | 授权领域 | 不是仅隐藏模型管理页面，也不妨碍普通用户使用受到业务接口控制的聊天能力。 |
| API 默认拒绝 | `/api/**` 默认须有有效 Sa-Token 登录态；仅完成认证本身所需的具体匿名动作可放行，且模型模块还须管理员权限。 | API 授权边界 | 不是整个 `/api/auth/**` 匿名放行，也不是由 Controller 自行漏检登录。 |
| 默认管理员激活 | 由部署配置预置账号名和邮箱的保留管理员账号，持有该邮箱者完成验证码验证并首次设置密码后才能使用的激活流程。 | 账号安全与部署边界 | 不是普通自助注册、固定初始密码或首个注册者自动提权。 |
| 默认管理员紧急恢复 | 默认管理员失联、禁用或失陷时，由部署级受控运维撤销原管理员凭据并恢复或替换管理员的流程。 | 部署与账号安全边界 | 不是公开找回接口、管理后台功能或在线角色委派。 |
| 普通用户（USER） | 仅在自身业务数据与所属租户边界内使用普通业务能力的已登录主体。 | 授权领域 | 不是模型网关或提示词管理的操作人。 |
| RBAC（角色权限控制） | 通过角色、权限和授权关系控制操作能力的授权领域能力；一期使用 `auth_role`、`auth_permission`、`auth_account_role`、`auth_role_permission` 四张表，初始化 `ADMIN` 与 `USER`。 | 授权领域 | 不是一期开放的自定义角色、组织成员或权限矩阵管理后台。 |
| 账号名（Account Name） | 用户输入、符合 GitHub 用户名规范且全局唯一的账号登录标识。展示时保留输入大小写，唯一性与登录匹配按 ASCII 小写规范化。 | 账号领域 | 不是可重复的显示昵称，也不是第三方平台返回的昵称。 |
| 账号名规范化键 | 账号名按 ASCII 小写转换后用于唯一性校验和登录匹配的值。 | 账号数据约束 | 不是改变展示账号名大小写的前端格式化。 |
| 旧账号名释放 | 账号名更换成功后，原账号名立即从该账号移除并可由其他账号按常规规则占用。 | 账号名变更流程 | 不是账号 ID 变更，也不改变历史业务数据的所有者。 |
| 第三方身份（External Identity） | QQ、飞书、Google 或 GitHub 在一次 OAuth 或扫码认证后确认的外部主体，与一个账号建立唯一绑定；成功登录会为新会话同时建立 15 分钟最近验证授权。 | 第三方认证领域 | 不是可由客户端直接提交并信任的第三方用户 ID，也不能跳过邮箱更换的双邮箱验证。 |
| 第三方身份唯一绑定 | 同一提供方和该提供方的同一外部主体在全系统中最多绑定一个 NexaRAG 账号，且不可由其他账号直接迁移取得。 | 第三方身份数据约束 | 不是一个账号只能绑定一个第三方身份。 |
| 二次验证（Step-up Authentication） | 在已登录会话之外，针对敏感操作再次证明当前账号控制权的短期认证；本期可使用当前已验证邮箱验证码或当前本地密码。 | 账号安全流程 | 不是仅检查已有 Sa-Token 会话，也不是重新输入第三方平台昵称。 |
| 最近验证授权 | 二次验证成功、邮箱验证码登录或第三方登录成功后，仅绑定当前账号和当前 Sa-Token 会话、有效期 15 分钟的服务端授权；可复用给第三方身份变更、设置/修改本地密码和设备会话撤销。账号名/邮箱密码登录不会自动签发。 | 账号安全流程 | 不是账号级或按自然日共享的授权，也不是三天登录态内永久有效的授权。 |
| 第三方身份变更 | 对当前账号执行第三方身份绑定或解绑的敏感操作，均需二次验证授权。 | 第三方身份绑定流程 | 不是普通第三方登录，也不是仅查询绑定列表。 |
| 首次第三方登录补全 | 未绑定的第三方身份认证成功后，要求用户输入合规且未占用的账号名；账号创建、身份绑定和登录在同一业务流程完成。 | 注册与登录流程 | 不是静默创建随机账号，也不是先登录既有账号再手动绑定。 |
| 邮箱自助注册 | 用户完成邮箱验证码验证后，输入合规账号名并设置符合密码策略的本地密码，创建 NexaRAG 账号的流程；成功自动登录时会建立 15 分钟最近验证授权。 | 注册与登录流程 | 不是仅绑定邮箱、不设置密码的资料编辑，也不要求先完成第三方登录。 |
| 注册后自动登录 | 邮箱自助注册成功后，服务端不要求用户再次输入凭据，而是直接签发新的 Sa-Token 会话 Cookie 并进入已登录状态。 | 注册与登录流程 | 不是复用注册前的匿名状态，也不绕过注册验证码的单次消费。 |
| 本地密码（Local Password） | 账号可选的账号密码登录凭据；通过第三方首次登录创建的账号初始不具备该凭据。 | 账号安全领域 | 不是第三方平台密码，也不会由服务端自动生成。 |
| GitHub 密码长度规则 | 一期本地密码须为至少 15 位任意字符，或至少 8 位且同时含小写字母与数字；泄漏密码/弱密码数据集检测暂不实施。 | 账号安全领域 | 不是强制要求特殊字符或大写字母，也不是一期必须接入外部泄漏密码检测。 |
| Argon2id 密码哈希 | 使用每个密码独立随机盐值的 Argon2id 生成的不可逆 PHC 格式哈希串，用于验证本地密码。 | 密码存储领域 | 不是可逆加密、快速 SHA 摘要或密码明文。 |
| 密码登录冻结 | 同一账号连续五次账号/邮箱密码登录失败后，服务端在 15 分钟内拒绝新的密码验证尝试；成功登录才可清空连续失败计数。 | 登录风控领域 | 不是永久锁定账号，也不阻止邮箱验证码或已绑定第三方身份登录。 |
| 设置/重置密码 | 已登录账号主动建立或更新本地密码的账号安全操作；适用于初始无密码和忘记原密码两种场景。 | 账号安全领域 | 不是第三方 OAuth 授权，也不改变第三方身份绑定关系。 |
| 密码凭据变更二次验证 | 已登录账号首次设置或修改本地密码前，使用当前已验证邮箱验证码或当前本地密码重新证明账号控制权的操作；可复用当前会话未过期的最近验证授权。 | 账号安全流程 | 不是普通会话操作，也不是可跨会话或长期复用的授权。 |
| 账号级会话撤销 | 对一个账号撤销其全部既有 Sa-Token 登录态的服务端操作；需要重新认证或重新建立会话后才可继续访问。 | 会话安全领域 | 不是仅删除当前浏览器的本地 Token。 |
| 重置密码后重新登录 | 密码重置成功并撤销全部既有会话后，用户需显式使用新密码、邮箱验证码或第三方身份重新登录；系统不自动建立新会话。 | 密码重置流程 | 不是复用重置前会话或重置成功后自动登录。 |
| 并发登录 | 同一账号可在多个设备或浏览器同时拥有有效 Sa-Token 登录会话；建立新会话不自动撤销旧会话。 | 会话安全领域 | 不是密码重置等账号级撤销后的旧会话继续有效。 |
| 设备会话 | 一个由服务端 Sa-Token 会话标识的独立登录实例，可被当前账号查询、单独撤销或随全局退出一起撤销；展示设备名称、随机 `deviceId`、时间、脱敏 IP 与市级约略地区。 | 会话安全领域 | 不是硬件指纹，也不暴露完整 Token 或完整 IP。 |
| 设备 ID（deviceId） | 服务端为浏览器配置文件生成的随机、非认证标识，用于将同一浏览器配置文件的会话归类展示；清理浏览器数据后可产生新 ID。 | 会话安全领域 | 不是硬件唯一 ID、授权凭据或可单独用于登录的 Token。 |
| 设备市级约略地区 | 服务端以登录请求 IP 解析得到的市级地区信息，用于会话列表和异常识别提示；VPN、代理或运营商网络下可能不准确。 | 会话安全领域 | 不是浏览器精确地理位置，不请求位置权限，也不参与认证或授权判断。 |
| IP 定位策略 | 将服务端可信客户端 IP 统一解析为市级约略地区的后端扩展点；可由配置选择 `local`、`tencent` 或 `amap` 实现，默认 `tencent`。 | 会话安全基础设施 | 不是前端上报的城市、硬件定位或登录授权依据。 |
| 退出所有设备 | 当前账号主动撤销其全部有效 Sa-Token 会话的安全操作。 | 会话安全领域 | 不是仅退出当前浏览器，也不删除账号或第三方身份绑定。 |
| 指定设备下线 | 当前账号选择一个设备会话并使该会话立即失效的安全操作。 | 会话安全领域 | 不是删除设备历史，也不影响其他未选中的会话。 |
| 滑动三天登录态 | 单个登录态初始有效期为三天；在到期前发生有效业务操作时，服务端将该登录态有效期重新延长三天。 | 会话安全领域 | 不是固定三天后必然失效，也不是配置独立更短的闲置超时。 |
| 会话 Cookie | 浏览器以 `HttpOnly`、`Secure`、`SameSite=Strict` 和 host-only 约束保存、自动传递的 Sa-Token 登录凭据。 | 会话安全领域 | 不是可被前端脚本读取并存入 `localStorage` 的 Token。 |
| 生产 HTTPS 前置条件 | 生产认证功能仅可通过 `https://xiaoxiaoliang.top` 发布；Nginx 终止 TLS 并反向代理 `/api/` 至本机 Spring Boot，受信任 CA 证书的申请与续期由 Nginx/部署工具处理。 | 部署与会话安全边界 | 不是允许以公网 HTTP 降级 Cookie 或 OAuth 安全属性。 |
| 设备标识 Cookie | 名为 `__Host-nexa-device-id` 的非认证 Cookie，用于持久保存浏览器配置文件的随机 `deviceId`；一年滑动有效，普通登出不清除。 | 会话安全领域 | 不是 Sa-Token、二次验证或 CSRF 凭据，也不是可被前端脚本读取的 `localStorage` 数据。 |
| CSRF 挑战 | 服务端签发给同源前端并要求在状态变更请求的自定义请求头中回传的防跨站请求伪造证明。 | 请求安全领域 | 不是 Sa-Token 本身，也不能替代登录认证。 |
| 已验证邮箱 | 已通过服务端发送并校验验证码、可证明账号控制权的邮箱地址。 | 邮箱认证领域 | 不是用户仅输入但尚未验证的邮箱，也不是第三方资料中的未验证邮箱声明。 |
| 首个邮箱绑定 | 无已验证邮箱的已登录账号，凭当前会话的最近验证授权和新邮箱独立验证码，为账号新增第一个邮箱登录与恢复凭据的流程。 | 账号安全流程 | 不是邮箱更换，不需要不存在的旧邮箱验码，也不能仅凭普通登录态完成。 |
| 邮箱验证码登录 | 用户使用当前已验证邮箱收到的一次性验证码完成的无密码登录方式；登录成功会为新会话同时建立 15 分钟最近验证授权。 | 邮箱认证领域 | 不是任意验证码都可登录，也不允许已撤销的旧邮箱登录或跳过邮箱变更的双邮箱验证。 |
| 邮箱验证码挑战 | 为特定邮箱和特定用途签发的 6 位数字验证码，五分钟内最多验证五次；同邮箱同用途的再次发送间隔至少 60 秒，重发会立即作废旧码；同一邮箱跨用途每日最多发送 10 次。 | 邮箱认证领域 | 不是可跨用途或长期复用的静态密码。 |
| 验证码 SMTP 投递 | 通过项目现有 SMTP 配置投递验证码邮件的统一服务；开发/集成环境可使用测试 SMTP，生产环境由部署配置注入真实凭据。 | 邮箱认证基础设施 | 不是将验证码写日志、返回给前端或直接调用专有邮件服务商 SDK。 |
| 安全操作通知 | 密码、邮箱、第三方身份或设备会话等高风险操作成功后，向当前已验证邮箱发送的脱敏告警邮件；邮箱更换同时通知旧、新邮箱。 | 账号安全流程 | 不是验证码、最近验证授权或可直接执行敏感操作的邮件链接。 |
| 安全活动 | 当前账号在安全页查看的近 90 天成功登录与敏感账号操作历史，包含脱敏的设备与地区摘要。 | 账号安全流程 | 不是其他账号的审计查询，也不展示密码、验证码、Token、完整 IP 或完整第三方主体 ID。 |
| 安全审计留存 | 服务端保存安全事件 180 天并按期清理的规则；禁用账号的记录仍按受控运维权限保留至到期。 | 安全审计领域 | 不是永久保存全部个人设备与地址信息。 |
| 邮箱唯一归属 | 同一已验证邮箱在全系统中只能归属一个账号，以唯一定位邮箱登录和密码重置的账号主体。 | 邮箱认证数据约束 | 不是一个账号只能拥有一项第三方身份。 |
| 双邮箱验证更换 | 账号更换邮箱时，必须分别完成旧邮箱和新邮箱的验证码校验后，才可提交邮箱归属变更；最近验证授权不可替代任一邮箱的验码。 | 账号安全流程 | 不是只验证新邮箱，亦不是仅凭当前登录会话或最近验证授权直接修改。 |
| 旧邮箱撤销与释放 | 邮箱更换成功后，旧邮箱立即失去该账号的登录、密码重置资格和唯一归属，可被其他账号经验证后使用；仅新邮箱保留原账号的邮箱凭据角色。 | 邮箱更换流程 | 不是保留旧邮箱作为永久或临时登录别名。 |
| 邮箱变更保留会话 | 成功更换邮箱不会撤销该账号既有 Sa-Token 会话；旧邮箱资格撤销与既有会话有效性是独立规则。 | 会话安全领域 | 不是允许旧邮箱继续登录、收取登录验证码或重置密码。 |
| 可用登录凭据 | 当前未失效且可用于完成 NexaRAG 登录的本地密码、当前已验证邮箱或已绑定第三方身份。 | 账号安全领域 | 不是已经注销、失效或仅保存但不可验证的凭据。 |
| 最后凭据保护 | 解绑操作不得使账号的可用登录凭据数量降为零。 | 第三方身份绑定流程 | 不是禁止用户解绑任意第三方身份，也不要求始终设置本地密码。 |
