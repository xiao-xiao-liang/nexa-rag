# 结构化章节索引重建手册

本文用于将已存在的文档补齐 `document_section`、`document_chunk.section_id` 与独立章节导航索引。重建会删除并重写目标文档的外部索引，必须按单文档执行，不能批量盲目操作。

## 1. 重建前检查

1. 确认应用已部署包含 `V16__add_document_section_structure.sql` 的版本，迁移已成功执行。
2. 确认目标文档状态、原文件可读性和当前处理配置；记录 `documentId`、文档标题、当前状态和操作人。
3. 确认 Elasticsearch、Milvus、Embedding 路由均可用；章节导航索引与正文索引名称必须分别为当前环境配置的 `navigation-index-name` 和正文索引名。
4. 检查当前没有同一 `documentId` 的处理任务在运行，避免旧索引清理与新索引写入交叉。
5. 从只读库或运维查询确认该文档的 `document_chunk`、`document_section` 现状，以便重建后核对数量和章节归属。

## 2. 单文档审批（必须单独取得）

每个 `documentId` 都需要一次独立、可追溯的批准。批准记录至少包含：环境、`documentId`、操作窗口、批准人、执行人，以及“允许删除该文档的正文和章节导航外部索引后重新处理”的明确确认。

未获批准时不得调用索引删除、重试或处理接口。一个文档的批准不能推及其他文档。

## 3. 执行步骤

1. 清理目标文档的外部索引。调用 `DELETE /api/document-indexes/{documentId}`；该操作依次清理向量、正文关键词和章节导航索引。记录三个阶段的删除结果及失败原因。
2. 通过 `POST /api/documents/{documentId}/retry` 提交该文档重试。此接口会进入既有的解析、切分、章节结构持久化和索引流程。
3. 轮询 `GET /api/documents/{documentId}/process-status`，直到状态为 `INDEXED` 或明确失败。失败时保留日志和索引清理结果，不要在没有新的单文档批准时反复重试。
4. 如需排查片段归属，使用 `GET /api/documents/{documentId}/chunks` 分页核对 `sectionId`，不要在日志或工单中复制正文内容。

## 4. 验证

1. `document_section` 中该文档的未删除章节数大于零（标题型 Markdown 文档除外，需记录例外原因）。
2. 有正文的 `document_chunk` 均具备正确的 `section_id`；章节标题导航记录只存在于导航索引，不得作为正文片段写入正文索引。
3. 在检索日志中核对：章节扩展日志只输出 `traceId`、文档/章节ID、计数、原因和预算；不得出现查询词、片段正文或提示词。
4. 针对章节问题执行受控人工验收：导航命中后只能补充其文档和后代章节范围内的原始正文；无足够正文时回答应按既有提示词明确说明资料不足，而非依据标题生成答案。
5. 记录最终文档状态、片段数量、章节数量、向量/正文/导航索引写入结果和验收人。

## 5. 后续度量（明确延期）

RAGAS、离线检索指标、答案质量指标和阈值自动校准不属于本次重建范围，当前明确延期。后续评估上线前应单独定义数据集、脱敏规则、指标口径、告警阈值及审批流程；不得将本手册中的默认候选数或 Token 预算视为已验证的质量指标。
