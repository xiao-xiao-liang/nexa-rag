# NexaRAG 身份认证、授权与租户设计

## 1. 目标与范围

本设计将当前固定开发用户认证替换为真实账号体系，并采用 Sa-Token 管理浏览器登录态。系统支持账号密码、邮箱密码、邮箱验证码、QQ 扫码、飞书扫码、Google 与 GitHub 登录；支持一个账号绑定多个第三方身份。

一期同时建立最小可演进的 RBAC 与企业租户模型：模型模块仅管理员可访问，普通业务数据按用户和当前租户隔离。本文只定义已确认的领域行为、边界和概念表，不固定数据库字段、索引、接口 JSON 结构或前端页面布局。

不在一期实现：在线角色/权限编辑、管理员委派、任意用户创建租户、完整多管理员治理、账号删除、密码泄漏库检查、浏览器精确地理位置、持久化第三方 access/refresh token。

## 2. 总体边界

```text
浏览器
  │  __Host- Sa-Token Cookie / CSRF 请求头
  ▼
Nginx（HTTPS、静态前端、/api/ 反向代理）
  ▼
Spring Boot
  ├─ Sa-Token 认证与当前主体上下文
  ├─ RBAC 授权：账号 → 角色 → 权限
  ├─ 租户成员资格与当前工作空间校验
  ├─ 身份、邮箱验证码、第三方 OAuth、设备会话、安全审计
  └─ 业务模块
       ├─ 普通业务 API：登录态 + 用户/当前租户范围
       └─ /api/model/**：登录态 + 管理员权限
```

认证、授权和数据范围均由服务端决定。客户端可展示账号、角色、当前租户和设备摘要，但不得提交或篡改 `userId`、角色、权限或当前租户来取得访问权。

## 3. 身份、账号与凭据

### 3.1 稳定标识

- `userId`：唯一不可变的认证、授权与业务用户标识，继续作为聊天等业务数据的所有者。
- `accountName`：用户的可变登录名称。改名不影响 `userId`、角色、租户成员资格或历史业务资源；旧名称立即释放。
- 不设置 `accountId` 或独立账号表；邮箱、密码、第三方身份、会话与全局 RBAC 均直接关联 `userId`。

新 ID 沿用项目现有的 `BIGINT`/IdWorker 体系。现有业务表的 `user_id VARCHAR(64)` 可继续存放 `userId` 的字符串形式，认证接入不得把该字段替换为账号名。

### 3.2 账号名与状态

账号名采用 GitHub 风格：1–39 个 ASCII 字符，仅允许字母、数字和单个连字符，不能以连字符开始/结束或连续出现。校验正则为：

```text
^[A-Za-z0-9]+(?:-[A-Za-z0-9]+)*$
```

展示保留用户输入大小写，唯一性和登录匹配按 ASCII 小写规范化键处理。

账号状态仅有 `ACTIVE`、`DISABLED`：

- 新账号为 `ACTIVE`。
- 禁用会立即撤销全部登录会话，拒绝所有认证入口和新会话建立；对外使用通用认证失败语义，实际原因写审计。
- 受控运维可重新启用账号，但不恢复旧会话、最近验证授权或验证码挑战，用户必须重新登录。

### 3.3 登录凭据

一个账号可以拥有当前已验证邮箱、本地密码和多个第三方身份；同一第三方提供方的稳定外部主体在全系统只能绑定一个账号。解绑会释放该绑定，但不允许把账号变成“没有任何可用登录凭据”。

首次第三方认证发现身份尚未绑定时，用户必须输入合规且未占用的账号名。账号创建、用户创建、默认租户归属、第三方身份绑定及登录为同一一致性流程，不能自动生成账号名、不能把第三方昵称/邮箱当账号名。

第三方首次创建的账号初始没有本地密码；可在通过邮箱验证或满足二次验证后设置。邮箱自助注册则在邮箱验证码成功后，输入账号名和密码，原子创建用户、账号、验证邮箱、密码和默认租户归属，并直接建立登录态。

## 4. 登录、密码与邮箱验证

### 4.1 支持的登录方式

- 账号名 + 本地密码；
- 已验证邮箱 + 本地密码；
- 已验证邮箱 + 邮箱验证码；
- 已绑定的 QQ、飞书、Google、GitHub。

第三方认证使用真实平台 OAuth/扫码能力：服务端处理 code 交换与稳定主体标识，`state` 服务端一次性保存并校验，支持的平台使用 PKCE；只申请最小范围，不持久化第三方 access/refresh token。生产回调统一为：

```text
https://xiaoxiaoliang.top/api/auth/oauth/{qq|feishu|google|github}/callback
```

GitHub 使用一个 GitHub App，可登记多个回调地址。所有 Client ID、Secret 与第三方密钥仅存在于部署环境变量或密钥管理系统。

### 4.1.1 平台协议固定契约

平台端点不允许通过应用配置覆盖；`nexa.auth.oauth` 只保存 Client ID、Client Secret 和对外 HTTPS 基址。提供方是否可用由 Client ID 与 Client Secret 是否完整决定。这样可避免因端点配置错误把授权码或 Token 发送给非官方地址。四个平台的实现契约如下：

| 平台 | 授权端点 | 授权码交换与稳定主体 | PKCE / 最小权限 |
| --- | --- | --- | --- |
| QQ | `https://graph.qq.com/oauth2.0/authorize` | 查询参数调用 `https://graph.qq.com/oauth2.0/token?fmt=json`，再调用 `https://graph.qq.com/oauth2.0/me?fmt=json`；只使用 `openid`。 | 不附加 `code_challenge`；不申请 `get_user_info`，不读取昵称、头像或邮箱。 |
| 飞书 | `https://open.feishu.cn/open-apis/authen/v1/authorize` | 先调用 `/open-apis/auth/v3/app_access_token/internal` 取得短期 app access token，再以 Bearer 调用 `/open-apis/authen/v1/access_token` 和 `/open-apis/authen/v1/user_info`；只使用当前应用下的 `data.open_id`。 | 该网页登录链路不附加 PKCE；应用后台须授予 `contact:user.base:readonly`。 |
| Google | `https://accounts.google.com/o/oauth2/v2/auth` | 表单 POST `https://oauth2.googleapis.com/token`，再以 Bearer 查询 `https://openidconnect.googleapis.com/v1/userinfo`；只使用永不复用的 `sub`。 | 强制 S256 PKCE；scope 固定为 `openid profile`。 |
| GitHub | `https://github.com/login/oauth/authorize` | 表单 POST `https://github.com/login/oauth/access_token`，再以 Bearer 查询 `https://api.github.com/user`；只使用数值 `id`，不使用可改名的 `login`。 | 强制 S256 PKCE；不申请额外 scope。 |

`state` 为 32 字节密码学随机值，服务端 Redis 保存 10 分钟且以 `GETDEL` 单次消费。它保存平台、动作、首次注册账号名、精确回调 URL、可选 PKCE verifier；绑定流程额外保存发起操作的 Sa-Token 值，但该值只存在 Redis，绝不回传浏览器、写日志或落库。由于 `SameSite=Strict` Cookie 不会随跨站回调发送，绑定回调按该 Token 重新确认同一 `userId` 的登录态仍有效，并检查同一 Token-Session 的最近验证授权未过期。

第三方登录在已有绑定时建立新的 Sa-Token 会话并签发最近验证授权；首次登录只在用户事先提交合规账号名时创建 `USER`、默认租户成员关系和外部身份绑定。绑定冲突由 `(provider_code, provider_subject)` 唯一约束最终裁决。绑定列表只展示 `externalIdentityId`、provider 和绑定时间，不返回主体 ID；解绑必须携带该记录 ID，并在锁定邮箱、密码和全部外部身份后执行，邮箱、密码和解绑目标以外的任一外部身份均可作为保留登录凭据。

### 4.2 密码策略

本地密码满足下列其一：至少 15 位任意字符；或至少 8 位且同时包含小写 ASCII 字母与数字。不在一期接入泄漏/弱密码数据集检测。

密码使用带独立随机盐的 Argon2id PHC 格式哈希保存，基线参数为内存 19,456 KiB、迭代 2、并行度 1；政策升级后在下一次验证成功时重哈希。

同一账号连续五次密码验证失败后，冻结密码验证 15 分钟；成功密码登录清除连续失败计数。该限制仅作用于密码登录，邮箱验证码和第三方登录仍可用。账号不存在、未设密码、密码错误和密码冻结均返回防枚举通用错误；同时施加可配置 IP 限制。

首次设置或修改本地密码需要当前密码或已验证邮箱验证码的二次验证，也可复用当前会话有效的最近验证授权。重置密码会撤销该账号全部会话，且不自动登录；设置或修改密码不撤销会话。

### 4.3 邮箱、验证码和更换邮箱

已验证邮箱全局唯一，完成服务端验证码验证后才能用于登录、密码重置和设置密码。

验证码规则：6 位数字、5 分钟有效、最多验证 5 次；同邮箱同用途重发间隔 60 秒，重发原子作废旧码；同一邮箱跨所有用途每天最多发送 10 次，按 Asia/Shanghai 自然日计算。验证码按用途和上下文绑定、服务端安全哈希保存、单次原子消费。验证码仅在 SMTP 投递成功后创建挑战，绝不写入日志或返回前端。

邮箱验证码可用于登录、验证/绑定邮箱、设置或重置密码、邮箱更换及敏感操作二次验证。用户更换邮箱时必须分别验证旧邮箱和新邮箱；成功后旧邮箱立即失去登录/重置/唯一归属资格并释放，新邮箱成为唯一可用邮箱凭据，既有会话保留。无邮箱的第三方账号首次绑定邮箱时，需要最近验证授权和新邮箱验证码。

邮件统一复用现有 SMTP 配置；生产凭据由部署注入，开发/集成环境可使用测试 SMTP。密码变更、邮箱变更、第三方绑定变更、设备会话撤销等成功后发送脱敏安全通知；通知投递失败不回滚安全操作，但需要异步监控。

## 5. 会话、二次验证与设备安全

### 5.1 Sa-Token 会话

登录态为三天滑动有效：有效业务操作会将当前会话续期三天，不设置独立闲置超时。允许同账号多设备并发登录，普通登录不踢出旧设备。

浏览器仅以 Cookie 传输登录态：Sa-Token Cookie 采用 `__Host-` 前缀、`HttpOnly`、`Secure`、`SameSite=Strict`、`Path=/`、不设置 `Domain`。前端不得在 `localStorage` 或自定义授权 Header 保存 Token。状态变更请求使用 CSRF Token 自定义 Header，并校验 Origin 和 Fetch Metadata。因 Strict Cookie 不会在跨站 OAuth 回调附带，OAuth `state` 由服务端独立保存与校验。

设备使用独立的 `__Host-nexa-device-id` 随机非认证 Cookie，按浏览器配置文件持久化、一年滑动有效，普通登出不清除。设备会话列表显示设备名称、随机 deviceId、登录时间、最近活动、脱敏 IP 和市级约略地区；不采集硬件指纹或浏览器精确地理位置。

用户可查看设备会话、踢出指定设备或退出所有设备。后两项要求最近验证授权，并立即在服务端撤销对应登录态。

### 5.2 最近验证授权

最近验证授权是服务端保存、仅绑定 `userId` 和当前 Sa-Token 会话、有效 15 分钟的短期二次验证凭据。它可被复用于第三方绑定/解绑、设置/修改密码、踢出设备和退出所有设备。

显式二次验证、邮箱验证码登录、第三方登录和邮箱自助注册自动签发该授权；账号密码和邮箱密码登录不自动签发。它在新会话、登出、会话撤销、密码重置造成的全账号会话撤销或到期时失效。邮箱双重更换验证与密码重置不使用该复用授权替代。

### 5.3 IP 地区与审计

可信客户端 IP 只接受来自受信任反向代理的地址链。IP 市级地区通过策略模式选择 `local`、`tencent`、`amap`，默认 `tencent`；配置无效或所选实现缺少必要密钥时应用启动失败。私有 IP、查询失败或超时只显示未知地区，绝不阻止登录。腾讯/高德密钥仅部署注入，高德实现需兼容其国内 IPv4 能力。

用户可查看本人近 90 天安全活动；服务端审计留存 180 天后可靠清理。事件包括成功登录、密码/邮箱/第三方凭据变更、设备撤销和账号状态变化，记录类型、结果、时间、设备摘要、脱敏 IP 与约略地区；不记录密码、验证码、Token、完整 IP 或完整第三方主体 ID。

## 6. 全局 RBAC 与 API 授权

全局 RBAC 采用以下四张概念表：

- `auth_role`：角色定义；
- `auth_permission`：权限定义；
- `auth_role_permission`：角色—权限关系。

一期初始化 `ADMIN` 和 `USER`。默认管理员拥有 `ADMIN`；所有自助注册和首次第三方创建的账号初始拥有 `USER`。一期不提供角色、权限、关联关系的在线编辑，也不允许管理员委派、转让或撤销其他账号的全局管理员角色。

`/api/**` 默认要求有效登录态。匿名放行只限完成认证所必需的具体动作：登录、注册、验证码挑战、密码重置、OAuth 发起/回调及默认管理员首次激活。已登录的账号设置、绑定解绑、设备管理、安全活动和普通业务接口仍须会话及各自的二次验证、范围校验。

`/api/model/**` 的全部接口均额外要求管理员权限，覆盖模型裸 Chat、提示词、路由、模型注册、供应商、模型配置和治理配置。普通用户仅能经受业务数据范围控制的常规业务接口间接使用模型能力。未登录返回未认证语义；已登录但无权返回未授权语义。

## 7. 默认管理员、历史数据与受控恢复

现有固定开发用户 `864019719617777664` 是既有业务 `userId`。迁移时将其补全为受控默认管理员用户，普通首个注册用户永远不会继承历史聊天数据。

部署配置预置默认管理员账号名和邮箱，但不包含初始密码、验证码或第三方密钥。应用初始化应幂等地保留/创建管理员用户、账号、RBAC 角色和历史数据映射；初始管理员没有可用密码、会话或第三方绑定。持有预置邮箱的人完成验证码验证并设置密码后才激活该账号和管理员能力。

若默认管理员邮箱失控、账号禁用或发生失陷，只允许部署级受控运维执行紧急恢复或替换：不提供公开 API、前端页面或普通管理入口。恢复必须撤销原管理员所有会话、最近验证授权、验证码挑战和可用登录凭据，接替管理员仍须通过部署预置邮箱完成首次激活。整个过程记录审批/工单标识（如有）、操作者、关联 ID、原因、时间和结果。

## 8. 租户与企业工作空间

### 8.1 默认租户与企业租户

新用户/账号自动加入共享内建默认租户，登录时默认进入该租户。租户以独立租户主数据表持久化，不能只存在于配置或业务字段中。全局管理员可通过受控管理能力创建新的企业租户；创建时创建者自动成为唯一初始 `OWNER`，并写入用户—租户成员资格关系。

租户成员资格连接不可变 `userId` 与 `tenantId`，与全局 RBAC 完全不同。租户内一期角色：

- `OWNER`：治理成员；可邀请、撤销未接受邀请、移除 `MEMBER`、发起所有者转交。
- `MEMBER`：使用该租户业务数据；可主动退出该企业租户。

二者都不因此获得全局 `ADMIN` 或模型模块权限。

### 8.2 邀请、退出与所有者转交

仅 `OWNER` 可邀请已有用户，按已验证邮箱或账号名定位但服务端必须解析唯一 `userId`。邀请本身不授权；受邀用户必须在登录态中明确接受，才建立有效 `MEMBER` 资格。邀请可被拒绝、撤销或过期，所有结果均不授予访问权并应审计。

`OWNER` 可移除普通成员；`MEMBER` 可以退出。二者都会立即撤销目标租户访问。唯一所有者不能自行退出，以避免无所有者租户。

所有者转交仅面向该租户现有成员：当前 `OWNER` 先完成最近验证，接收成员登录后明确接受才生效；成功后原所有者降为 `MEMBER`。这不改变全局角色，也不转移资源到其他租户。

### 8.3 当前租户会话上下文

当前 `tenantId` 保存在服务端 Sa-Token 会话状态。用户切换工作空间时，服务端先检查目标成员资格有效，再更新该会话的当前租户；业务请求不可用路径、参数、Header 或前端缓存中的 tenantId 覆盖它。

每次读写、异步处理、缓存访问和流式执行边界均须核验当前成员资格与租户状态。成员被移除或租户禁用后，立即拒绝该租户访问；受影响会话在下一次请求自动回退默认租户，但账号其余登录态与其他租户资格保留。

## 9. 概念数据模型与实现约束

实现阶段至少需要下列领域实体及其关联；字段名、索引、唯一约束细节将在数据库设计评审中确定。

| 领域 | 概念实体/关系 | 核心约束 |
| --- | --- | --- |
| 用户与账号 | 用户及其账号名/凭据属性 | 仅 `userId` 不可变；账号名可变。 |
| 本地凭据 | 密码凭据、邮箱凭据、邮箱验证码挑战 | 已验证邮箱全局唯一；验证码用途/上下文绑定、单次消费。 |
| 外部凭据 | 第三方身份绑定、OAuth state | 提供方 + 稳定外部主体全局唯一；不保存第三方 Token。 |
| 会话与安全 | Sa-Token 会话、最近验证授权、设备摘要、安全审计 | 会话/授权撤销服务端立即生效；审计数据最小化。 |
| 全局授权 | 用户角色、角色、权限、角色—权限 | 基于 `userId` 读取；不根据账号名或客户端参数授权。 |
| 租户 | 租户、用户—租户成员、租户邀请 | 成员关系连接 `userId` 与 `tenantId`；租户内角色不等同于全局 RBAC。 |

所有创建/绑定/接受/转交/撤销等跨实体敏感操作必须具备事务一致性、竞争唯一约束与幂等语义；失败不得留下孤立账号、凭据、成员关系、邀请或可用会话。

## 10. 验收与测试重点

实现前后的自动化测试至少覆盖：

1. 账号名规范化、唯一性、改名释放与不可变 ID 归属。
2. 各登录方式、首次第三方补全、凭据唯一绑定、解绑最后凭据保护。
3. 密码 Argon2id、失败冻结、防枚举、重置全会话撤销与设置/修改密码二次验证。
4. 邮箱验证码用途隔离、发送/验证次数限制、双邮箱更换、旧邮箱释放及 SMTP 失败行为。
5. Cookie 属性、CSRF、OAuth state/PKCE、三天滑动会话、多设备与指定设备撤销。
6. 最近验证授权的签发、会话绑定、15 分钟到期和各种撤销路径。
7. `ADMIN`/`USER` RBAC、`/api/**` 默认拒绝、`/api/model/**` 管理员保护、401/403 区分。
8. 默认管理员幂等初始化、历史 `userId` 归属、首次邮箱激活与受控恢复。
9. 租户创建、邀请接受/拒绝/撤销/过期、成员移除/退出、当前租户切换、回退与所有者双确认转交。
10. 审计脱敏、留存清理、IP 定位策略故障降级，以及异步/流式操作中的成员资格复验。
