# 知识库前端重构设计

**日期：** 2026-07-29
**状态：** 待评审
**范围：** 知识库总览、文档列表、文档分块浏览与编辑

## 1. 目标

将知识库调整为会话优先工作台中的独立功能页。用户从固定左侧栏点击“知识库”后，在右侧完成文档上传、处理状态查看、文档浏览、文本分块阅读与编辑。

视觉语言采用克制的 Dify 式信息层级：浅色背景、白色内容面、12 像素圆角、靛蓝主操作色、轻量边框和状态标签。不得复用 Dify 的商标、插画、截图或文案。

## 2. 信息架构与路由

左侧栏始终保留会话历史和功能配置入口；知识库相关路由只替换右侧内容。

| 路由 | 页面 | 作用 |
| --- | --- | --- |
| `/knowledge-base` | 知识库总览 | 展示默认知识库、最近文档、处理中和失败提醒 |
| `/knowledge-base/documents` | 全部文档 | 服务端分页浏览、上传、进入文档详情、删除或处理文档 |
| `/knowledge-base/documents/:documentId/chunks` | 文档分块 | 浏览、选择、编辑和保存指定文档的文本分块 |

当前后端没有独立的知识库实体，因此首期仅呈现“默认知识库”，不伪造多知识库创建、切换、统计或权限能力。

## 3. 页面设计

### 3.1 知识库总览

页面头部显示“知识库”和“上传文档”主操作。首屏主体为默认知识库概览卡，展示文档总数、已索引数量、处理中数量和失败数量；下方展示最近文档及状态，并提供“查看全部文档”入口。

处理中区域按“解析 → 切分 → 索引”表达当前阶段，失败区域只提示失败文档数并链接至文档详情。没有服务端汇总契约时，不在正式页面显示聚合数字或阶段统计；保留对应骨架屏位置。

### 3.2 全部文档

页面使用服务端分页表格，列固定为：文档（标题与原始文件名）、类型、处理状态、操作。

操作由文档状态决定：

- `UPLOADED`：查看详情、开始处理、删除。
- `QUEUED`、`PARSING`、`CHUNKING`、`INDEXING`：查看详情、删除；不显示重复提交。
- `INDEXED`：查看详情、查看分块、删除。
- `FAILED`：查看详情、重新处理、删除。

首期不展示文件大小、上传时间、分块总数、跨页关键词搜索和按状态筛选，因为当前文档列表接口未返回或不支持这些字段。页面搜索仅在当前页客户端数据上生效，并明确使用“搜索当前页文档”文案。

### 3.3 文档分块

页面顶部保留文档类型、文件名、文件大小、处理状态与返回文档入口。选择“文本分块”标签后，主区使用卡片网格展示当前页分块；每张卡片包含来源文件、标题（正文首个有效行）、正文摘要、分块序号和状态。

点击卡片后，右侧固定预览栏更新为对应分块。预览栏依次显示来源文件、完整正文、字符数和取消/保存操作。编辑时正文使用可调整高度的文本域；切换其他分块、返回文档或关闭页面前，如存在未保存修改，必须二次确认。

分块卡片与右侧预览栏的选择状态只在当前页面维护，分页切换后清空选中项。当前页检索按正文和分块序号过滤，不伪装为服务端全文检索。

## 4. 接口边界

已存在且继续使用的接口：

| 能力 | 接口 |
| --- | --- |
| 文档列表 | `GET /api/documents?pageNum&pageSize` |
| 上传文档 | `POST /api/documents/upload` |
| 文档详情 | `GET /api/documents/{documentId}` |
| 处理状态 | `GET /api/documents/{documentId}/process-status` |
| 开始处理 | `POST /api/documents/{documentId}/process` |
| 失败重试 | `POST /api/documents/{documentId}/retry` |
| 文档分块 | `GET /api/documents/{documentId}/chunks?pageNum&pageSize` |
| 删除文档 | `DELETE /api/documents/{documentId}` |

为支持用户确认的“编辑后保存”，后端需新增接口：

`PATCH /api/documents/{documentId}/chunks/{chunkId}`

请求体仅包含 `text`；服务端校验分块归属、文本非空和长度上限，返回更新后的分块对象。更新成功后应保证检索索引与关键词索引同步刷新；若同步采用异步任务，响应应返回明确的更新状态，前端不得将其直接标记为完成。

在该接口发布前，正式前端只展示只读预览，不显示可点击的“保存修改”。高保真原型可保留编辑交互，用于确认体验，但不得接入生产路由。

## 5. 状态与异常

- 文档详情处于处理中时，继续以 5 秒间隔轮询处理状态；到达 `INDEXED` 或 `FAILED`、离开路由或组件卸载时立即停止。
- 分块只在文档处于 `INDEXED` 时加载；其他状态显示处理进度和不可用原因。
- 编辑保存失败时保留用户输入，内联显示原因与重试入口。
- 删除、开始处理和重新处理均显示进行中状态，防止重复提交。
- 所有加载、空数据和网络失败状态均在所属区域显示，不能遮蔽已成功加载的文档信息。

## 6. 验收标准

1. 用户可从左侧“知识库”进入默认知识库总览，并回到会话而不丢失会话历史。
2. 文档列表仅展示后端已提供字段；状态对应的操作准确可用。
3. 已索引文档可进入分块卡片工作区；选择卡片后右侧展示完整内容。
4. 分块编辑保存仅在更新接口发布后启用；保存成功、失败、未保存离开均有明确反馈。
5. 375px、768px、1024px 和桌面宽度下不产生主内容横向溢出；图标按钮具有可访问名称和明显键盘焦点。
