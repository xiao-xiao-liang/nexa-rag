# 飞书 Block Markdown 渲染设计

## 目标

将飞书 Docx 的扁平 Block 列表按父子关系重建后渲染为 Markdown，消除高亮块、表格及表格单元格的数字占位符，并保留可检索文本和文档结构。

## 问题

飞书“获取文档所有 Block”接口返回的是带 `block_id`、`parent_id`、`children` 的扁平 Block 集合。当前实现逐项转换，既没有从页面根节点遍历，也没有识别容器 Block。因此高亮块（19）、表格（31）和表格单元格（32）会输出未解析占位符；同一段内容还可能因父子关系被重复或乱序写入。

## 设计决策

1. 先以 `block_id` 建立索引，从页面根 Block（类型 1）按 `children` 深度优先遍历；同一 Block 最多渲染一次，缺失子节点和循环引用直接跳过，保证导入不中断。
2. 文本、九级标题、无序/有序列表、代码块、引用和待办继续转换为 Markdown。类型 17 为待办，类型 22 为分割线。
3. 高亮块（19）、分栏（24/25）、引用容器（34）等只承载子内容，不再输出内部类型占位符。高亮块使用 Markdown 引用形式保留视觉分组语义。
4. 表格（31）根据 `table.cells`、`row_size` 与 `column_size` 定位单元格（32），递归汇集每个单元格的子文本并生成 Markdown 表格。单元格只由所属表格渲染，不作为独立正文重复输出。
5. 图片、文件、电子表格、流程图等无文本外部内容输出可读类型名称占位，例如 `[飞书图片]`；不再暴露内部数字。未知且无文本的 Block 输出 `[未支持的飞书内容]`。

## 范围

仅修改 `FeishuBlockMarkdownConverter` 的渲染逻辑。读取 API、快照格式、对象存储和后续切分索引流程不变。

## 验收标准

- 示例文档不再出现 `[未解析飞书块：19]`、`[未解析飞书块：31]`、`[未解析飞书块：32]`。
- 表格内容以行列结构进入 Markdown，单元格文本不重复输出。
- 标题树可以在标题前没有正文时被现有切分器识别。
- 非文本嵌入内容仍对检索读者可见，但不泄露内部 Block 类型编号。
