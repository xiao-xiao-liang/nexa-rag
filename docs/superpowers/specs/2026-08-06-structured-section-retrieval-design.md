# 结构化章节检索设计

## 目标

修复“标题被召回、答案正文未进入上下文”的系统性问题。对于可识别标题层级的 Word、PDF 和 Markdown 文档，标题仅承担章节定位职责，最终回答只使用经过排序的正文证据。

当命中上级标题或章节定位结果时，系统只在该章节后代正文中补充最相关的 2 至 3 个片段，并受 Token 预算限制；证据仍不足时必须拒答。

## 范围与非目标

### 范围

- 为 Word、PDF、Markdown 解析产物建立可查询的章节树。
- 区分章节层级关系与超长文本窗口切块关系。
- 使用“文档标题 + 标题路径 + 正文”生成索引文本。
- 增加内容检索、章节导航、有限后代正文扩展和保守拒答。
- 清空现有向量索引后，以新流程全量重新处理存量文档。
- 保留候选、排序、章节扩展和拒答的必要运行日志，供后续评测系统采集。

### 非目标

- 不为 Excel 或纯文本伪造章节关系；它们保持既有表格、行或窗口切块策略。
- 不保留旧向量索引与新索引的并行服务或灰度切换能力。
- 不改变回答模型的事实约束：低置信或不完整证据必须拒答。
- 不在本次变更中实现前端引用展示或章节树浏览界面。
- 不在本次变更中建设标注检索集、RAGAS 评测流程、指标看板或基于评测的自动参数调优。

## 领域模型

```text
Document
├── DocumentSection（标题层级）
│   ├── sectionId
│   ├── parentSectionId
│   ├── title / headingPath / level / 文档位置
│   └── ContentChunk（可回答正文）
│       ├── chunkId
│       ├── sectionId
│       ├── rawContent
│       └── indexContent
└── 非结构化窗口块（无 Section，仅保留既有窗口关系）
```

`DocumentSection` 表达 Markdown 标题祖先、子孙关系。`parentChunkId` 仅表达同一正文因超过窗口长度而形成的切块关系；二者不得复用同一字段。

章节至少持久化 `section_id`、`document_id`、`parent_section_id`、`title`、`heading_path_json`、`heading_level`、`start_line`、`end_line`、创建与更新时间，并沿用项目既有的 `del_flag` 逻辑删除字段。正文片段至少新增可查询的 `section_id` 和用于索引的 `index_content`；现有 `text` 保持原始正文，供详情展示和回答上下文使用。为兼容本次改造前的既有写入链路，迁移阶段的 `index_content` 允许为 NULL；完成新切分链路后，每个新写入正文块必须赋值，索引端不得接受空索引文本。

## 解析与切块

1. 标题扫描器使用标题栈建立 `DocumentSection` 树，不再在遇到下一标题时把空的上级标题生成为普通正文片段。
2. 有实质正文的章节按 Token/窗口长度生成 `ContentChunk`，每个块关联当前章节。
3. 纯标题只保存章节节点，不写入正文向量或正文关键词索引。
4. `indexContent` 固定由文档标题、完整标题路径和原始正文构成；Embedding 与 BM25 使用它，回答模型使用 `text` 原文。
5. Word、PDF、Markdown 的解析产物若没有可用标题层级或层级异常，退回既有窗口切块并标记为非结构化；该文档不参与章节后代扩展。
6. Excel 和纯文本继续使用现有切分器，不新增章节节点。

## 索引与检索流程

### 索引

- 内容向量索引与内容关键词索引只写入 `ContentChunk`。
- 章节导航索引单独保存 `DocumentSection` 的标题和标题路径；它只产生“章节范围”，绝不直接成为回答证据。
- 外部索引返回结果必须携带 `documentId`、`sectionId`、`chunkId`、内容类型和原始正文定位信息。

### 常规路径

```text
问题改写
  ↓
内容向量召回 + 内容 BM25 召回
  ↓
宽松粗过滤、RRF 融合、候选数量截断
  ↓
有限数量 Rerank
  ↓
证据质量判定
  ├── 可信：按 Token 预算组装原始正文
  └── 偏弱：进入章节定向扩展
```

粗过滤不是最终相关性判定。向量候选数、BM25 候选数、粗过滤下限、RRF 截断深度与 Rerank 上限均应是可版本化运行配置，不能针对单个案例写死。正式参数校准由后续 RAGAS 评测系统完成；本期仅保留可观测性并采用保召回的初始配置。

### 章节定向扩展

当常规路径为空、正文过短、候选只具章节定位价值、Rerank 结果低置信或证据不完整时：

1. 使用已生成的查询向量或关键词查询章节导航索引，获得候选章节范围。
2. 在命中章节的后代 `ContentChunk` 中，以同一检索问题进行二次候选和 Rerank。
3. 仅补充最相关的 2 至 3 个正文块；超过上下文 Token 预算时按排序从低到高裁剪。
4. 扩展后仍无法形成足够完整、可信的证据时，执行保守拒答。

不得按 `chunkOrder` 固定追加相邻片段，也不得把整个章节的全部子节注入上下文。

## 证据质量与拒答

最终质量判定使用评测后的 Rerank 分数、候选类型、正文长度、问题覆盖度、分数差距和上下文完整性等信号。任一低置信或不完整场景不得让回答模型基于部分资料推断；回答应明确说明现有资料不足。

## 全量重建

本次不要求在线迁移：

1. 预检全部待处理文档是否仍有可读取的原始文件和解析产物。
2. 删除现有向量索引中的文档片段数据与过时章节导航数据。
3. 执行新的解析、章节建模、切块、Embedding 与索引流程。
4. 对每份文档校验正文块、章节关系、向量写入与关键词写入状态。
5. 仅在全部文档处理结束后，使用评测集验证检索质量并发布调优配置。

重建期间不承诺旧知识库检索可用；失败文档可依据保留的原始文件和解析产物单独重试。

## 本期验证与后续评测

本期只交付单元、集成和端到端回归测试，至少覆盖纯标题不作为正文证据、标题路径进入索引文本、有限后代正文扩展、非结构化降级和低置信拒答。现有“微调的目录有什么规范”是必备回归用例。

RAGAS 评测、标注集、Recall@K、MRR、NDCG、回答质量、拒答质量、延迟和成本的系统化比较，作为后续独立评测系统建设。本期日志应保留足够的候选数量、筛除原因、章节扩展范围、最终证据块标识和拒答原因，方便未来接入评测系统。

## 错误处理与可观测性

- 标题结构缺失或异常：记录结构化降级原因，正常完成窗口切块和索引。
- 章节导航、BM25 或向量单通道失败：记录通道失败并按既有降级策略继续其余通道；最终没有充分证据时拒答。
- 二次章节扩展失败或超出 Token 预算：不追加不完整内容，回到保守拒答。
- 日志与指标记录候选数量、筛除原因、章节扩展范围、最终证据块标识和拒答原因；不得记录 API Key 或完整敏感提示词。

## 实施边界

该设计涉及文档模块、检索模块、对话工作流、外部向量/关键词索引模式、数据库迁移和测试资源。实施计划必须逐项列出表结构、索引集合、接口模型、重建命令、回归测试和评测脚本，且在重建操作前进行独立审批。
