# 知识库单文件上传体验改版设计

## 背景与目标

当前知识库上传弹窗直接暴露原生文件控件及两个输入框，缺少文件投放、已选文件反馈、客户端预校验和上传中状态，不符合成熟知识库产品的使用预期。

本次改版仅优化单文件上传体验，保持现有 `POST /api/documents/upload` 接口及“上传成功后跳转文档详情页”的行为不变。

## 范围

### 纳入范围

- 拖拽文件到上传区或点击上传区选择单个文件。
- 初始态、拖拽态、已选文件态、校验失败态、接口失败态和上传中态。
- 自动从文件名生成可编辑标题；描述作为可选补充信息。
- 客户端按后端实际能力预校验文件扩展名和单文件大小。
- 已选文件的文件类型图标、文件名、文件大小、替换和移除操作。
- 单元与组件测试覆盖核心状态和提交契约。

### 不纳入范围

- 多文件队列、批量上传、并发控制与断点续传。
- 实时字节级上传进度；当前接口不提供进度事件。
- 云盘导入、URL 导入、文件夹上传。
- OCR、解析、切分、索引等高级配置。

## 约束与契约

后端目前支持 `pdf`、`doc`、`docx`、`xls`、`xlsx`、`csv`、`ppt`、`pptx`、`md`、`markdown`、`txt` 文件，单文件限制为 100MB。前端预校验只负责缩短反馈路径；后端仍是最终校验方。

请求继续使用现有 `FormData`：

- `file`：选中的单个文件。
- `request`：仅包含 `title` 和 `description` 的 JSON Blob。

## 交互设计

### 初始态

弹窗内容区使用大面积虚线拖拽区：上传图标、主文案“拖拽文件到这里”、次文案“或点击选择文件”，以及支持格式和 100MB 限制。拖入有效文件时，边框和背景高亮。

拖拽区本身可点击，也应能通过键盘触发原生文件选择，隐藏的原生 `<input type="file">` 仍是唯一文件来源。

### 已选文件态

选择成功后，拖拽区收敛为文件卡片：

- 根据扩展名显示类型图标。
- 显示原始文件名、文件格式和格式化后的文件大小。
- 提供“更换文件”和移除按钮。
- 标题自动填入去掉扩展名后的文件名，用户可修改。
- 描述默认以“添加描述（可选）”展开入口呈现，避免干扰首次上传。

### 校验和错误态

选择或拖入不支持格式、空文件、超过 100MB 的文件时，前端不调用接口，在上传区或文件卡片下提示明确原因，并允许立刻重新选择。

接口提交失败时，保留文件、标题和描述，只展示接口错误；用户可以直接再次提交或更换文件。成功后调用既有 `onUploaded(documentId)`，跳转文档详情页。

### 上传中态

点击“开始上传”后显示“正在提交并创建处理任务”，禁用开始上传、更换、移除、取消和关闭。接口返回后恢复交互或跳转详情。由于没有真实进度事件，不显示虚假的百分比或进度条。

## 组件边界

- `UploadDocumentDialog`：管理表单状态、拖拽事件、客户端校验、提交和错误信息。
- `FileDropzone`：纯展示和交互层，接收文件状态及选择、替换、移除回调。
- `file-upload.ts`：文件扩展名、格式名称、图标类别、文件大小格式化、标题推导和校验等纯函数。

页面 `KnowledgeBaseListPage` 继续只控制弹窗开关及上传成功后的路由跳转。

## 可访问性

- 上传区具有可读名称、键盘焦点样式和 Enter/Space 触发选择能力。
- 错误信息使用 `role="alert"`。
- 替换、移除按钮有明确的无障碍名称。
- 上传中所有不可用控件保持语义化禁用状态。

## 测试策略

- 文件工具：格式识别、大小边界、标题生成与大小格式化。
- 弹窗组件：点击选择、拖入、格式/大小拒绝、自动标题、替换、移除、失败保留输入、提交 FormData 和上传中禁用。
- 既有列表页回归：上传成功仍路由到 `/knowledge-base/:documentId`。

## 参考依据

Notion、Google Drive、Dropbox 的官方说明均将点击上传和拖拽上传作为标准入口。此设计沿用该模式，但根据当前单文件接口，避免引入多文件队列和虚假的进度表现。
