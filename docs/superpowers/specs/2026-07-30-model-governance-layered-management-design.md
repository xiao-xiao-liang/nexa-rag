# 模型治理分层配置设计

## 目标

将模型治理配置改造成可编译校验的局部更新模型，同时支持模型配置级和路由级策略。路由级策略覆盖模型配置级；已保存且关闭的路由级策略是显式关闭，不回退。

## 架构

`ModelGovernanceConfigConverter` 使用 MapStruct 完成实体响应转换和非空 PATCH 映射。治理配置的绑定身份由资源路径确定：模型配置级使用 `configId`，路由级使用 `routeId` 解析出的 `routeKey`；请求体不包含身份字段。

数据库以 CHAT 策略为字段默认值的唯一来源。自动创建时仅写入绑定字段和 Embedding/Rerank 相对 CHAT 的差异字段，插入后回查完整记录。无已保存记录的查询成功返回 `data: null`。

运行时先查路由级配置。存在且关闭时返回关闭策略；存在且启用时使用路由级策略；缺失时回退最终选中模型配置的策略。注册表快照必须保留关闭的路由级记录，才能表达显式关闭。

## 接口

- `GET`、`PUT /api/model/configs/{configId}/governance`：管理 CONFIG 绑定。
- `GET`、`PUT /api/model/routes/{routeId}/governance`：管理 ROUTE 绑定。
- 两类 `PUT` 延续已有局部更新语义：请求中为 `null` 的字段保持原值。

## 一致性与刷新

路由 `routeKey` 改名时，路由记录和关联 ROUTE 治理配置在同一事务中更新。版本号只递增一次，刷新消息在事务提交后发布，所有实例重建包含新路由和新治理索引的完整注册表快照。

## 验收

1. 新增映射字段遗漏会在编译阶段失败。
2. PATCH 不覆盖未提交字段，且不允许更改绑定身份。
3. CHAT 默认值来自数据库；Embedding/Rerank 只写差异。
4. 路由级启用、缺失、显式关闭三种状态分别产生覆盖、回退、关闭结果。
5. 改名后旧路由 key 无治理记录，新 key 保留原治理配置，并只刷新一次。
