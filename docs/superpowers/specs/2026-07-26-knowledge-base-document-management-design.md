# 知识库文档管理一期设计

## 1. 背景与目标

`nexa-rag-front` 已具备 RAG 对话和会话管理能力。本期基于已发布的文档接口，新增知识库文档管理，使用户能够上传文档、观察处理进度、处理失败后重试，并在索引完成后检查文本分块。

本期坚持“接口优先”：只实现现有服务端契约已经提供的能力，不以前端临时状态伪造服务端筛选、文件预览或高级处理配置。

## 2. 范围

### 2.1 本期实现

- 增加窄全局侧栏；“对话”和“知识库”为可进入模块。
- 增加可刷新、可回退的前端路由：`/chat`、`/knowledge-base`、`/knowledge-base/:documentId`。
- 文档服务端分页列表、上传、删除。
- 独立文档详情页，展示元数据、处理状态、失败信息与处理操作。
- 对处理中详情每 5 秒轮询处理状态；离开详情或到达终态后停止。
- 仅在文档已索引时展示分块分页列表。

### 2.2 明确不实现

- OCR、图片描述、切分策略、索引开关等高级处理配置表单。
- 按状态的服务端筛选视图；现有列表接口仅支持 `pageNum`、`pageSize`。
- 原文件、解析文件的打开或预览。
- 模型中心页面、未来 Agent 的真实入口。
- RAG 检索引用展示。

这些事项已记录于根目录 `TODO.md`。

## 3. 领域模型

| 术语 | 含义 | 所有者 | 非含义 |
| --- | --- | --- | --- |
| 文档 | 知识库中持久化的文件及其处理结果，标识为 `documentId` | 服务端 | 不是一次处理任务，也不是浏览器上传临时文件 |
| 处理批次 | 某次文档流水线执行，标识为 `processId` | 服务端 | 不用于前端详情路由 |
| 文档状态 | 文档处理生命周期状态 | 服务端 | 前端不可自行修改或推断成功 |
| 文本分块 | 从文档解析、切分后得到的可索引文本单元，标识为 `chunkId` | 服务端，归属文档 | 不是完整原文或文件预览 |
| 上传草稿 | 上传弹窗中尚未提交的文件、标题和描述 | 前端临时状态 | 不持久化，也不等同于文档 |

### 3.1 文档状态模型

服务端事实状态为：`UPLOADED → QUEUED → PARSING → PARSED → CHUNKING → CHUNKED → INDEXING → INDEXED`。失败可从可处理阶段进入 `FAILED`，并由重试回到 `QUEUED`。

前端将 `QUEUED`、`PARSING`、`CHUNKING`、`INDEXING` 视为“处理中”，每 5 秒轮询 `GET /api/documents/{documentId}/process-status`。`INDEXED` 和 `FAILED` 为轮询终态；组件卸载或路由离开也必须停止轮询。

`UPLOADED` 显示“开始处理”，调用 `POST /api/documents/{documentId}/process`。`FAILED` 显示“重新处理”，调用 `POST /api/documents/{documentId}/retry`。其他处理中状态不提供重复提交入口。

## 4. 信息架构与路由

采用“窄全局侧栏 + 模块页面”的结构：

- `/chat`：保留当前会话列表与 RAG 对话工作台。
- `/knowledge-base`：知识库文档列表。
- `/knowledge-base/:documentId`：独立文档详情页。

全局侧栏本期仅包含可用的“对话”“知识库”入口；不展示无页面、不可操作的模型中心占位项。

## 5. 页面与交互

### 5.1 文档列表页

- 通过 `GET /api/documents?pageNum&pageSize` 加载服务端分页数据，默认每页 20 条。
- 仅展示接口已提供的标题、原始文件名、文件类型、处理状态和操作。
- 提供上一页、下一页与页码信息，不添加状态筛选、关键字搜索或客户端跨页过滤。
- 提供“上传文档”按钮，打开上传弹窗。
- 列表加载、空列表、加载失败均有对应状态；失败时可重试本次列表请求。
- 删除操作必须先经过二次确认。删除成功后保持在列表页并重新加载当前页；若当前页因删除为空，则回退到上一有效页。

### 5.2 上传弹窗

- 使用 `POST /api/documents/upload` 的 `multipart/form-data` 契约。
- 必填文件；标题、描述可选。
- 不传 `splitConfig`、`parseConfig`、`indexConfig`，由后端应用默认处理配置。
- 上传成功收到 `documentId` 后立即进入详情页，并由详情页承担状态轮询。
- 以明确的上传中、失败、可重试状态防止重复提交。

### 5.3 文档详情页

- 使用 `GET /api/documents/{documentId}` 获取元数据，展示标题、描述、文件名、类型、文件大小和文档状态。
- 使用 `GET /api/documents/{documentId}/process-status` 展示处理批次、消息状态、消费次数，以及失败阶段和失败原因。
- 不展示 `originalFileUrl`、`parsedFileUrl`。
- 已索引时提供“文本分块”区，使用 `GET /api/documents/{documentId}/chunks?pageNum&pageSize` 服务端分页；未索引时说明分块暂不可用。
- 详情、处理状态与分块请求各自具备加载、空态、失败重试，不能让某一请求失败遮蔽已加载内容。

## 6. 前端边界与错误处理

- 扩展现有 `ApiError`，继续统一处理网络异常、HTTP 异常和业务非成功码。
- 路由切换时取消或忽略已过期的列表、详情、状态和分块请求，避免晚到响应覆盖新页面数据。
- 轮询请求失败不会清空最近一次有效的状态；显示可重试提示，并在下一轮正常轮询前保持可见。
- 前端不推导文档权限、文件 URL 权限或后端未提供的状态筛选结果。

## 7. ADR

### ADR-004：采用窄全局侧栏与独立知识库路由

- 背景：对话工作台的左侧会话列表只属于对话上下文，不能承载持续扩展的中台模块。
- 决策：使用窄全局侧栏切换“对话”“知识库”，知识库详情使用独立路由。
- 备选：顶部模块导航；列表右侧详情抽屉。
- 理由：侧栏结构可扩展，独立详情页可容纳状态、分块及后续高级配置。
- 后果：前端引入路由；现有对话入口迁移至 `/chat`。

### ADR-005：上传使用后端默认处理配置

- 背景：上传接口支持完整处理配置，但首期不需要暴露 OCR、图片描述、切分和索引的复杂参数。
- 决策：仅提交文件、可选标题、描述，省略全部高级配置。
- 备选：上传时直接展示完整高级表单。
- 理由：减少配置错误，先验证文档入库的核心闭环。
- 后果：高级配置后续补充，不改变现有上传接口。

### ADR-006：仅轮询处理中详情状态

- 背景：处理状态接口是当前唯一实时性契约。
- 决策：每 5 秒轮询处理中详情；终态、路由离开或组件卸载即停止。
- 备选：全列表轮询；完全手动刷新。
- 理由：降低请求量，同时让上传后进度可见。
- 后果：列表不会伪装为实时看板；详情是状态观察的主入口。

### ADR-007：不实现状态筛选与文件预览

- 背景：文档列表接口没有状态参数，文件 URL 的访问权限策略未确认。
- 决策：本期不提供状态视图、原文件或解析结果链接。
- 备选：前端仅过滤当前页；直接打开后端返回 URL。
- 理由：避免不完整筛选误导用户，避免绕过未确认的对象存储访问控制。
- 后果：待后端契约与权限策略明确后，按 TODO 扩展。

## 8. 验收标准

- 文档列表、详情可通过 URL 刷新、复制链接、浏览器前进后退正确访问。
- 上传成功后进入对应详情页；处理中状态自动更新且终态停止轮询。
- `FAILED` 文档能显示失败阶段和失败原因，并可调用专用重试接口。
- `INDEXED` 文档可分页浏览分块；未索引文档不请求或展示分块内容。
- 删除有二次确认，完成后列表数据与分页正确刷新。
- 不出现未有接口支撑的状态筛选、文件预览或高级配置表单。
