# ADR：设置或修改本地密码前必须二次验证当前账号凭据

## 状态

已接受。

## 背景

首次设置本地密码会为原本仅能第三方登录的账号增加新的登录入口；修改已有密码会替换现有凭据。若只依赖已有 Sa-Token 会话，盗用会话的一方可取得长期密码登录能力。

## 决策

1. 已登录账号首次设置本地密码或修改已有本地密码前，必须完成二次验证；已有 Sa-Token 会话本身不足以授权该操作。
2. 二次验证可使用当前已验证邮箱的一次性验证码，或在已有本地密码时验证当前密码。
3. 首次设置密码必须使用当前已验证邮箱验证码，不能以不存在的当前密码或第三方资料替代。
4. 当前 Sa-Token 会话存在有效最近验证授权时可免除本次重复验证；首次设置本地密码仍不得使用不存在的当前密码作为验证方式。
5. 验证成功或复用最近验证授权后，服务端签发仅限当前账号、当前密码变更用途、短期且单次消费的授权挑战；提交新密码时必须消费该挑战并再次执行 GitHub 密码策略和 Argon2id 哈希存储。
6. 首次设置或修改本地密码成功后，不撤销该账号既有 Sa-Token 会话；密码重置的全量会话撤销规则保持不变。

## 备选方案

### 仅凭已有登录会话设置或修改密码

拒绝。盗用会话可直接建立或替换本地密码，形成持久化账号接管。

### 首次设置密码要求输入当前密码

拒绝。第三方首次创建的账号按设计没有本地密码，无法提供该凭据。

### 复用同一会话内永久有效的授权

拒绝。三天滑动登录态可能长期有效，不能使密码控制能力被无限期授权；最终采用当前会话内 15 分钟的最近验证授权，并保留每项操作的单次挑战隔离。

### 首次设置或修改密码后撤销全部会话

拒绝。用户明确要求该类已认证凭据管理操作不打断已有多设备会话；忘记密码重置仍作为疑似凭据泄露场景执行全量撤销。

## 后果

- 账号安全页需要分别驱动密码设置、密码修改和密码重置流程，不能合并为仅提交新密码的普通接口。
- 服务端必须审计密码凭据变更结果与二次验证方式，但不得记录密码、验证码、哈希中间值或完整会话 Token。
- 此决策不会自动改变邮箱更换、第三方身份变更或密码重置的既有会话策略；其中只有密码重置触发账号级全量会话撤销。
