# ADR：第三方首次登录创建的账号初始不设置本地密码

## 状态

已接受。

## 背景

首次第三方登录会在用户补全合规账号名后创建 NexaRAG 账号。系统同时支持账号密码登录，但第三方认证本身并不能证明用户希望建立或已安全接收本地密码。

需要明确新账号的本地密码状态，避免在首次授权完成时强制收集密码，或由服务端生成用户未知的初始密码。

## 决策

1. 通过第三方首次登录创建的账号初始不设置本地密码。
2. 账号安全功能必须提供设置本地密码和重置本地密码的能力。
3. 未设置本地密码的账号不得使用账号密码方式登录；已绑定的第三方登录方式仍可使用。
4. 设置或重置密码时的身份验证、密码规范、限流、会话失效和审计要求由后续安全设计单独定义。

## 备选方案

### 首次第三方登录时强制设置密码

拒绝。增加首次登录摩擦，且用户可能仅希望使用第三方身份登录。

### 服务端生成默认密码

拒绝。默认密码易被遗忘或暴露，不满足可验证的凭据交付和安全要求。

### 永不支持第三方创建账号设置本地密码

拒绝。限制了用户切换到账号密码登录的能力，也不满足账号密码登录方式的产品范围。

## 后果

- 账号数据模型需要可表达“未设置密码”，不能用空密码哈希、固定默认值或第三方资料替代。
- 登录页应在未设置密码时给出明确失败原因，但不得泄露账号是否存在以外的敏感信息。
- 设置/重置密码将成为敏感操作；后续必须定义可信身份验证渠道和账户恢复策略。
