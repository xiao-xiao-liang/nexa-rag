# ADR：按生成任务与事件版本恢复 SSE 流

## 背景

长时间的模型生成可能因网络波动中断浏览器与服务端的 SSE 连接。若前端只标记失败，用户会丢失后续实时输出；若重新发起原问题，可能重复执行工具并产生不同结果。持续轮询又会引入无效请求和额外延迟。

## 决策

前端在 SSE 非主动关闭时自动重连，并携带 `generationId` 和最后成功应用的 `lastEventVersion`。服务端验证当前用户对生成任务的访问权后，从该版本之后按顺序补发尚未收到的事件，并继续推送实时事件。

每个实时工具状态更新和 Markdown 正文增量都具有同一生成任务内单调递增的事件版本；前端忽略已处理版本，确保重连补发幂等。正常连接期间不轮询后端。

## 备选方案

1. 断线后提示用户手动重试原问题。
2. 断线后重新执行整轮生成。
3. 通过定时轮询任务状态和回答全文恢复。

## 理由

按版本补发能继续当前生成而不重复调用工具；SSE 保持实时推送优势，前端可通过版本去重处理网络重试和重复帧。

## 后果

- 服务端需要为运行中的生成任务保留短期、有序的可重放事件缓冲。
- 恢复接口或恢复请求必须校验生成任务归属，不能仅凭 `generationId` 读取事件。
- 前端需要区分主动取消与异常断线；只有后者触发自动恢复。
- 事件缓冲过期或任务已经终态时，前端改用最终快照或历史消息接口纠偏。
