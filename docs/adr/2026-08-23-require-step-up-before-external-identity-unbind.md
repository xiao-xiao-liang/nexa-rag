# ADR：解绑第三方身份前必须二次验证当前账号凭据

## 状态

已接受。

## 背景

第三方身份是账号的可用登录凭据之一。即使服务端已阻止解绑最后一种可用凭据，盗用既有会话的一方仍可能解绑部分身份，破坏用户的恢复入口或改变账号安全配置。

## 决策

1. 解绑第三方身份前，账号必须完成二次验证；已有 Sa-Token 会话本身不足以授权解绑。
2. 二次验证方式与绑定第三方身份一致：当前已验证邮箱的一次性验证码，或已设置本地密码的当前密码验证。
3. 解绑时仍必须在同一事务中执行最后凭据保护，防止账号失去全部可用登录凭据。
4. 当前 Sa-Token 会话存在有效最近验证授权时可免除本次重复验证；其有效期、撤销条件和用途范围由统一最近验证策略定义。在未获得该授权前，任何绑定或解绑请求均不得执行。

## 备选方案

### 仅对绑定要求二次验证

拒绝。解绑同样改变账号的登录和恢复入口，盗用会话可借此破坏账号可恢复性。

### 仅依赖最后凭据保护

拒绝。该规则只能阻止移除最后一项凭据，不能防止攻击者移除其他重要绑定。

### 仅凭 Sa-Token 会话解绑

拒绝。与绑定操作的会话盗用风险相同，不足以证明操作者有权修改敏感凭据。

## 后果

- 绑定与解绑前端流程需要共享同一二次验证入口，但服务端挑战必须按具体操作用途隔离。
- 解绑失败、最后凭据保护拒绝和二次验证失效均不得改变第三方身份绑定记录。
- 绑定与解绑都应写入安全审计日志，且日志不得包含密码、验证码、Token 或授权码。
