# ADR：账号名采用 GitHub 用户名规则

## 状态

已接受。

## 背景

第三方首次登录创建 NexaRAG 账号时，用户需要补全一个合规账号名。项目此前没有账号名规范，若未在服务端固定长度、字符范围和唯一性规则，前后端及后续登录接口会产生不一致。

用户已决定账号名与 GitHub 用户名规则保持一致。GitHub 官方文档说明用户名仅包含字母数字和连字符、不能超过 39 个字符，并禁止以连字符开始或结束及连续两个连字符；其外部身份规范化流程保留大小写展示。 [GitHub 用户名规范化说明](https://docs.github.com/en/enterprise-cloud%40latest/admin/managing-iam/iam-configuration-reference/username-considerations-for-external-authentication)

## 决策

1. 账号名长度为 1 至 39 个 ASCII 字符。
2. 账号名只允许 ASCII 字母、数字和单个连字符（`-`）；不得以连字符开始或结束，且不得含连续连字符。
3. 服务端校验正则为 `^[A-Za-z0-9]+(?:-[A-Za-z0-9]+)*$`，并另行校验最大长度。
4. 展示时保留用户输入的大小写；唯一性检查和账号名登录匹配使用 ASCII 小写规范化键，因此大小写不同的名称不可被不同账号占用。
5. 账号名以先到先得方式占用；已被占用时必须选择其他名称，不提供普通流程下的转让或回收。
6. 账号名允许更换；更换成功后，旧账号名立即释放，可由其他账号按同一规范重新占用。
7. 账号名更换仅要求当前账号的有效 Sa-Token 登录态、当前账号归属校验和新账号名规范/唯一性校验，不要求最近验证授权或额外邮箱验证码。

## 备选方案

### 允许中文、下划线或任意 Unicode 字符

拒绝。与用户选择的 GitHub 规则不一致，并会提高跨端规范化与视觉混淆处理复杂度。

### 仅由前端限制格式

拒绝。服务端接口、并发创建和直接调用仍会产生非法或冲突账号名。

### 区分大小写占用不同账号名

拒绝。会制造视觉近似的不同登录主体，增加误登录与用户混淆风险。

### 账号名更换要求最近验证授权

拒绝。账号名不是邮箱、密码或第三方身份等恢复与登录凭据的控制权证明；在保留有效登录态、原名称立即释放和审计记录的前提下，避免为常规资料变更增加二次验证摩擦。

## 后果

- 账号表需同时保存展示账号名和唯一的规范化键；规范化键必须有数据库唯一索引。
- 补全账号名、账号密码登录和账号名变更功能必须复用同一服务端校验与规范化逻辑。
- 所有业务归属、鉴权和审计必须使用不可变 `accountId`，不得将可变且会被复用的账号名作为外键或授权主体。
- 账号名变更接口需要在同一事务中完成新名称占用检查、旧名称释放和展示值更新，并处理并发冲突。
- 账号名变更必须写入安全审计日志，记录不可变 `accountId`、变更前后账号名、执行会话和时间；日志不得包含会话 Token 或 Cookie 值。
