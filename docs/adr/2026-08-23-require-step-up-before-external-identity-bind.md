# ADR：绑定第三方身份前必须二次验证当前账号凭据

## 状态

已接受。

## 背景

登录会话允许多设备并发且具有三天滑动有效期。若仅凭现有 Sa-Token 会话即可绑定新的第三方身份，盗用会话的一方可能绑定其控制的第三方账号，进而建立持久的登录入口。

## 决策

1. 发起第三方身份绑定前，账号必须先完成二次验证，已有 Sa-Token 会话本身不足以授权绑定。
2. 本期二次验证可使用当前已验证邮箱的一次性验证码，或已设置本地密码的当前密码验证。
3. 已存在于当前 Sa-Token 会话的有效最近验证授权可替代本次重新验证；若不存在或已过期，二次验证成功后，服务端签发最近验证授权，并同时签发仅限当前账号、绑定用途、短期有效且单次消费的授权挑战；第三方 OAuth/扫码完成后必须关联并消费该挑战。
4. 绑定前仍须完成第三方提供方的服务端认证，并执行第三方身份全局唯一绑定检查。

## 备选方案

### 仅凭已有登录会话绑定

拒绝。会话被盗时可被用来植入攻击者长期控制的第三方登录入口。

### 只要求完成待绑定第三方的 OAuth 或扫码

拒绝。只能证明操作者控制待绑定身份，不能证明其有权修改当前 NexaRAG 账号的登录入口。

### 每次只允许输入本地密码

拒绝。第三方首次创建且尚未设置本地密码的账号无法安全完成绑定；当前已验证邮箱验证码可提供统一的二次验证通道。

## 后果

- 绑定 API 需要显式的二次验证阶段和短期挑战状态，前端必须先完成该阶段再展示第三方授权入口。
- 二次验证挑战与 OAuth `state` 均需一次性消费、绑定目标账号并防重放；错误、过期和账号不匹配时不得执行绑定。
- 审计日志应记录绑定尝试、二次验证结果和提供方类型，但不得记录密码、验证码、完整 Token 或第三方授权码。
