# ADR：支持邮箱验证、账号名与本地密码的自助注册

## 状态

已接受。

## 背景

若账号只能由第三方首次登录创建，用户必须先拥有并使用 QQ、飞书、Google 或 GitHub 身份，才能启用账号密码和邮箱密码登录。用户已确认应支持不依赖第三方身份的邮箱自助注册。

## 决策

1. 提供邮箱自助注册入口：用户先完成注册用途的邮箱验证码验证，再提交合规且未占用的账号名与符合本地密码策略的密码。
2. 注册成功时，在同一一致性流程中创建账号、建立已验证邮箱归属、保存 Argon2id 密码哈希并建立默认租户归属。
3. 注册使用的邮箱验证码仅能用于注册流程，不得复用于邮箱登录、密码重置、邮箱变更或二次验证。
4. 注册流程必须复用账号名唯一性、邮箱唯一归属、弱密码拦截、验证码限流和防枚举策略；并发冲突必须拒绝，不得覆盖既有账号或邮箱归属。
5. 注册成功后，服务端直接为新账号建立一个新的 Sa-Token 登录态、写入加固会话 Cookie，并为该新会话签发 15 分钟最近验证授权；用户无需返回登录页再次认证。

## 备选方案

### 仅支持第三方首次登录注册

拒绝。会排除不使用受支持第三方平台或不愿授权第三方身份的用户。

### 先创建未验证账号，再异步验证邮箱

拒绝。会产生不可登录或可被滥用的半成品账号，也无法把邮箱作为可信登录与恢复凭据。

### 邮箱注册不要求设置密码

拒绝。用户已明确要求邮箱自助注册包含设置密码；无密码账号应仅来自已确认的第三方首次登录流程。

## 后果

- 注册 API 需要以短期、单次消费的注册验证码挑战驱动，不能信任客户端传入“邮箱已验证”标记。
- 账号创建失败时必须原子回滚或补偿邮箱归属、默认租户关系和密码哈希写入，避免任何孤立记录。
- 前端需提供账号名可用性、密码策略和邮箱验证码状态的清晰反馈，但服务端仍为最终校验方。
- 注册验证码必须在账号创建事务中被原子认领并标记为已消费；重复提交不得创建多个账号或多个独立注册会话。
- Sa-Token 会话和最近验证授权必须随注册成功原子建立；注册或会话建立失败时不得留下可用的最近验证授权。
