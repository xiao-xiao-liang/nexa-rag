# ADR：检索默认覆盖当前租户全部知识库，并支持多知识库缩小范围

## 状态

已接受。

## 背景

引入多知识库后，现有 RAG 检索不能继续从无边界的全局文档集合检索。调用方既需要开箱即用地检索当前组织全部知识，也需要在任务明确时只检索一个或多个选定知识库。

## 决策

1. 未指定知识库时，RAG 检索默认覆盖当前租户内的全部可访问知识库。
2. 检索请求可携带一个或多个知识库标识，以缩小检索范围；空集合与未提供均表示默认全范围，不表示“检索不到任何库”。
3. 服务端必须在检索前验证每个指定知识库属于当前租户且调用方有访问权限；非法或无权标识不得被静默忽略。
4. 向量、关键词及结构化章节检索的索引记录均需保存知识库标识，并在查询阶段执行范围过滤；不得仅在合并结果后用应用层过滤。
5. 后续组织成员权限上线后，“全部可访问知识库”由当前身份的授权集合确定；本期单租户下等同于默认租户全部未删除知识库。

## 备选方案

### 每次检索强制指定一个知识库

拒绝。增加默认使用门槛，且不满足跨多个业务资料库联合问答的场景。

### 始终检索租户全部知识库，不支持选择

拒绝。无法限制噪声、控制检索成本，也不能满足明确业务范围的问答。

### 先检索全局再在应用层过滤

拒绝。会产生跨库候选泄露风险、浪费检索资源，并使召回排序失真。

## 后果

- 聊天/检索请求 DTO、前端选择状态和测试需要新增可选的知识库标识集合。
- 向量、关键词和章节索引写入与查询契约需要增加知识库过滤字段；已有索引应根据文档回填归属重建或安全回填。
- 检索服务要明确区分“未指定范围”和“指定了无权/不存在范围”的错误语义。
