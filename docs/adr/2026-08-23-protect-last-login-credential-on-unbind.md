# ADR：解绑不得移除账号最后一种可用登录凭据

## 状态

已接受。

## 背景

NexaRAG 允许一个账号绑定和解绑多个第三方身份，且第三方首次创建的账号初始没有本地密码。若用户能够解绑最后一个可用第三方身份，账号将无法再次由用户自行登录。

需要将解绑限制定义为服务端不变量，而非依赖前端按钮显示状态。

## 决策

1. 账号解绑第三方身份前，服务端必须确认解绑后仍至少保留一种可用登录凭据。
2. 可用登录凭据为已设置且有效的本地密码、当前已验证邮箱，或任一仍有效的已绑定第三方身份。
3. 若解绑会使可用登录凭据数量降为零，服务端必须拒绝请求，并提示用户先设置本地密码或绑定另一第三方身份。
4. 该检查必须与解绑写入在同一事务中完成，以避免并发解绑导致账号不可登录。

## 备选方案

### 允许解绑最后一种凭据

拒绝。会造成用户无法自行恢复的不可登录账号。

### 仅由前端隐藏最后一个解绑按钮

拒绝。客户端状态可过期或被绕过，无法保证并发和直接 API 调用的安全性。

### 强制所有账号都设置本地密码

拒绝。与第三方首次登录不强制设置密码的既定体验冲突，且不需要为保护可登录性而引入该摩擦。

## 后果

- 解绑接口需要查询并锁定账号当前凭据状态，防止多个并发请求各自错误判断仍有剩余凭据。
- 账号安全页需要展示本地密码是否已设置及第三方绑定状态，但最终授权由服务端执行。
- 凭据失效、第三方撤销授权和账户恢复策略将影响“可用”的判定，需在后续安全设计中明确。
