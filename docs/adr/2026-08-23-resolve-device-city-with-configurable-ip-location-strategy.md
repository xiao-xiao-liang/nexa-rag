# ADR：设备市级地区采用可配置 IP 定位策略

## 状态

已接受。

## 背景

设备会话列表需要展示登录 IP 对应的市级约略地区。不同部署环境对地区数据的准确性、网络可达性、成本和隐私边界有不同需求；将地图服务调用写死在会话服务中会造成供应商耦合，也无法在离线环境使用本地库。

## 决策

1. 后端定义独立的 `IpLocationStrategy` 扩展点，输入服务端可信链路解析出的客户端 IP，输出统一的省/市级约略地区结果；会话、登录和审计领域不得依赖腾讯或高德的响应 DTO。
2. 一期提供三个策略实现：`local`（本地 IP 地理库）、`tencent`（腾讯地图 IP 服务）和 `amap`（高德地图 IP 服务）。通过应用配置选择且仅启用一个实现，默认使用 `tencent`。
3. 配置值限定为 `local`、`tencent`、`amap`；配置缺失、非法或所选实现必需配置缺失时，应用启动必须明确失败，不得静默切换到其他供应商。
4. 腾讯和高德的 API Key、签名密钥或其他凭据只能通过环境变量或密钥管理注入；不得提交到仓库、暴露给前端或写入日志。`local` 策略的库文件路径及更新方式同样由部署配置提供。
5. 策略实现必须设置连接与读取超时、最小化重试，并将供应商结果规范化为内部地区值。地区解析失败、私网地址、未知地址或供应商不可用时，只记录“地区未知”，不得阻断登录、会话建立、二次验证或会话撤销。
6. 对 `tencent` 或 `amap` 策略，服务端仅向选定供应商发送解析市级地区所需的客户端 IP；该 IP 不得写入接口响应、通知邮件或业务日志。用户界面须标示地区为“约略位置”。
7. 高德策略必须适配其 IP 定位接口的能力边界：其官方文档当前说明仅支持 IPv4 和国内 IP；不支持的地址统一返回“地区未知”。 [高德 IP 定位文档](https://developer.amap.com/api/webservice/guide/api/ipconfig)
8. 一期生产部署由本机 Nginx 反向代理至 Spring Boot；后端仅当连接对端为受控 Nginx 的本机地址 `127.0.0.1`（或后续明确配置的 Unix Socket）时，才信任其覆盖后的 `X-Real-IP`/`X-Forwarded-For`。任何绕过受控代理的连接，或来自其他地址的转发头，均不得信任。

## 备选方案

### 在会话服务中直接调用腾讯地图

拒绝。会将会话核心逻辑与单一供应商耦合，无法满足本地库和高德的可配置切换要求。

### 让浏览器调用地图服务并上报城市

拒绝。客户端结果可被伪造，并会暴露地图服务密钥或引入浏览器定位权限；市级地区应由服务端基于可信请求 IP 解析。

### 无条件信任 X-Forwarded-For 或 Forwarded 请求头

拒绝。客户端可直接伪造这些头；只有来自受控本机 Nginx 的连接，且其已覆盖转发头为实际连接对端地址时，后端才可使用该值。

### 地区解析失败时拒绝登录

拒绝。地区仅用于安全展示与辅助识别，第三方定位服务的可用性不应成为账号登录的单点故障。

## 后果

- Spring Boot 配置需包含策略类型，以及 `local`、`tencent`、`amap` 各自独立的配置段；同时须启用原生转发头处理并将可信代理严格限制为 `127.0.0.1`。接口、配置属性类、策略实现和供应商 DTO 必须分层，避免供应商字段扩散。
- 部署文档需列出腾讯地图和高德地图 IP 服务的申请项、密钥注入方式、超时配置和本地库更新说明，但不得记录真实 Key。
- 测试必须覆盖三种策略选择、非法配置启动失败、供应商响应规范化、私网/IPv6/未知地址、超时降级和不影响登录的行为。
