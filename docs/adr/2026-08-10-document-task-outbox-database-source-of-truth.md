# ADR：文档任务与 Outbox 分离，并以数据库作为最终事实源

## 状态

已接受。

## 背景

现有 `document_task_outbox` 同时保存任务执行状态和消息投递状态。两种生命周期、重试策略和并发租约彼此独立，放在同一记录中会导致状态含义混杂，且已出现任务消费状态未完整回写、发布最终失败无法按任务失败处理等问题。

系统还需要降低高频 Outbox 扫描带来的数据库压力，但不能以牺牲故障恢复、审计和最终一致性为代价。

## 决策

1. 新建 `document_task` 保存文档异步任务的业务事实，包括任务身份、文档、执行版本、父任务、任务类型、执行状态、执行租约、失败信息与完成时间。
2. `document_task_outbox` 只保存可靠投递事实，包括关联任务、消息键、消息载荷、投递状态、下次发布时间和发布租约。
3. `document_task` 与初始 Outbox 记录必须在同一数据库事务中创建；数据库是任务、投递和幂等性的唯一最终事实源。
4. Redis 仅作为可丢失、可重建的调度加速层：提交后通知 Publisher、延迟任务唤醒、限流和热点去重。Redis 不保存唯一任务事实，不作为唯一队列，也不单独决定任务成功或失败。
5. 发布和消费的正确性由数据库条件更新保证。每次抢占分别使用发布 `claimToken` 和执行 `executionToken`；租约过期后的旧持有者不得凭旧 token 回写状态。
6. RocketMQ 与 Redis 都按 At-Least-Once 使用。消费者必须依赖任务状态机及数据库唯一约束保证幂等；对外部副作用额外使用业务幂等键。
7. `parentTaskId` 表达工作流父子关系；`parentOutboxId` 仅可作为消息/告警溯源信息，不能承担任务树身份。
8. 同一文档同一时间只允许一个未终态的 `PROCESS_DOCUMENT` 任务。旧任务处于待发布、发布中、待消费或执行中时，拒绝创建新的处理版本；只有旧任务进入终态后才允许重新提交或人工重试。
9. Outbox 发布达到最大尝试次数但仍未被 MQ 确认时，视为关联任务的最终失败。对于 `PROCESS_DOCUMENT`，必须在同一数据库事务中将任务与文档标记为失败、记录脱敏原因并创建最终失败告警任务；随后才允许人工重试创建新的操作版本。
10. 所有任务处理器按 `taskId` 提供 At-Least-Once 幂等性。租约超时、Publisher 重发和 RocketMQ 重投都可能产生重复消息；文档处理、外部索引清理、对象存储清理和飞书/邮件告警不得因重复执行产生额外业务副作用。
11. 首期只实施数据库正确性闭环：拆分任务与 Outbox、数据库条件租约、RocketMQ 消费幂等、过期租约回收和数据库对账扫描。Redis 调度加速不进入首期运行路径，仅保留后续扩展边界；只有压测证明数据库扫描是瓶颈后才单独引入。
12. 终态任务与终态 Outbox 记录不直接删除，必须归档以保留人工补偿、审计和故障追溯能力。记录进入终态后在线保留 30 天，随后归档；归档介质和脱敏策略在后续决策中明确。

## 备选方案

### 仅使用 Redis 队列、锁和状态

拒绝。Redis 无法与文档数据库事务和 RocketMQ 发送形成统一原子提交；故障恢复、长期审计、幂等约束和过期锁的旧持有者隔离均不足。

### 仅使用数据库轮询

保留为正确性兜底。低吞吐阶段可以先使用具备合适索引和条件抢占的数据库轮询；当扫描成为瓶颈时再增加 Redis 加速，不让 Redis 成为新的单点事实源。

### 继续复用单张 `document_task_outbox`

拒绝。投递失败与任务执行失败属于不同的状态机、重试策略和运维动作，继续混合会扩大状态组合并阻碍人工补偿。

## 后果

- 需要迁移表结构、实体、Mapper、管理查询与人工重试接口。
- 发布器和消费者必须以短事务领取租约，网络调用和外部副作用在事务外执行，回写时校验对应 token。
- Redis 宕机时吞吐会下降或回退到数据库扫描，但任务不能丢失；需要提供对账扫描和过期租约回收。
- Redis 的具体加速模型（Stream、ZSet 或二者组合）需要根据延迟任务规模、运维能力和观测要求另行确定。
- 前端和接口需能明确返回“已有进行中的处理任务”及其任务标识，避免调用方将并发拒绝误判为临时系统失败。
- 发布失败不再仅是运维可见的 Outbox 异常；它会成为用户可见的文档处理失败，需要与消费失败采用一致的告警、查询和人工补偿入口。
- 消费者测试必须覆盖同一 `taskId` 的重复投递、执行租约交接和“外部副作用已成功但状态回写失败”三种场景。
- 首期不增加 Redis 可用性、持久化、Stream 消费组或延迟队列的运维负担；代价是需要为数据库扫描设计正确索引、批量领取和观测指标。
- 在线工作表只保留调度与近期查询所需数据；归档数据不参与 Publisher 的待发布扫描。
- 归档作业必须以终态时间为边界，且仅迁移已超过 30 天的终态记录；不得迁移待发布、发布中或执行中的记录。
