# ADR：高风险账号安全操作后通知已验证邮箱

## 状态

已接受。

## 背景

最近验证、双邮箱验证和会话撤销可阻止大量未授权安全变更，但用户仍需要在发生意外或未经本人确认的操作时尽快获知。安全通知是低打扰的补充控制，不应承担身份验证或授权职责。

## 决策

1. 下列操作成功后，向当前已验证邮箱发送安全通知：密码重置、首次设置或修改本地密码、绑定或解绑第三方身份、绑定首个邮箱、指定设备下线、退出所有设备。
2. 更换邮箱成功后，同时向旧邮箱和新邮箱发送安全通知；旧邮箱通知只告知变更已发生与异常处理入口，不得包含新邮箱完整地址、验证码或可直接执行敏感变更的链接。
3. 通知邮件只包含操作类型、发生时间、必要的设备/会话摘要和异常处理指引；不得包含密码、验证码、Sa-Token、Cookie、第三方访问令牌、完整 IP 地址或精确地理位置。
4. 安全通知不构成验证码、最近验证授权或操作挑战，未阅读、退信或发送失败不得逆转已经原子完成的安全操作。
5. 尚无已验证邮箱的账号没有可用邮件通知目标；此类操作仍必须保留安全审计记录，直到用户完成首个邮箱绑定。

## 备选方案

### 不发送安全操作通知

拒绝。用户难以及时发现会话被盗用、凭据或外部身份被意外变更，且不会减少实际验证步骤。

### 用通知邮件中的链接或内容继续授权操作

拒绝。会混淆通知与认证授权边界，并扩大邮件转发、泄露或钓鱼后的风险。

### 通知发送失败时回滚安全操作

拒绝。安全操作已经完成身份校验与原子提交，邮件服务可用性不应使已完成的密码重置、会话撤销或凭据变更进入不一致状态。

## 后果

- 通知应通过现有 SMTP 基础设施异步投递，并以受限的安全审计或投递状态支撑故障观测；不得将邮件内容、验证码或凭据写入日志。
- 前端安全中心应提供与通知中一致的安全事件记录或异常处理入口，具体展示与留存策略后续定义。
- 测试须覆盖各事件的收件人选择、邮箱变更双通知、无邮箱账号、脱敏内容和邮件发送失败不回滚业务结果。
