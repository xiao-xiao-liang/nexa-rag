# ADR：逻辑删除的聊天数据不自动物理清理

## 背景

会话删除已定义为会话、消息和 Redis 缓存的一致逻辑删除。物理清理需要额外定义保留期、归档位置、恢复窗口、批量任务容量控制和误删处置，当前产品未提出这类需求。

## 决策

逻辑删除的 `chat_conversation` 与 `chat_message` 不执行自动物理删除或归档。业务查询、历史消息接口、LLM 上下文构建和 Redis 缓存读取始终排除逻辑删除数据。

## 备选方案

1. 逻辑删除后按固定保留期物理清理。
2. 将冷历史迁移到归档存储。
3. 用户删除时立即物理删除。

## 理由

当前无需引入不可逆清理、归档和恢复策略的运营复杂度；逻辑删除提供一致的用户不可见语义，并为未来受控排障或合规策略保留空间。

## 后果

- 聊天表容量会持续增长，需要监控逻辑删除数据占比、索引体积和查询延迟。
- 后续如引入物理清理，必须通过新的 ADR 定义授权、保留期、执行窗口和恢复/审计边界。
- 所有新增查询必须明确使用 MyBatis-Plus 逻辑删除能力或等效条件，避免删除数据泄露。
