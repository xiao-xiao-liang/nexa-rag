# ADR：邮箱密码登录及密码重置只接受已验证邮箱

## 状态

已接受。

## 背景

NexaRAG 支持邮箱密码登录、设置密码和重置密码。邮箱既是登录标识，又可能成为找回本地密码的控制渠道；未经验证的邮箱不能证明其由当前账号主体控制。

## 决策

1. 邮箱必须通过服务端发送并校验的验证码后，才能作为账号的邮箱登录凭据。
2. 仅已验证邮箱可用于邮箱密码登录、设置密码和重置密码。
3. 用户输入、第三方资料返回或客户端声称的邮箱在完成验证前均不得用于上述安全操作。
4. 无已验证邮箱的第三方创建账号，必须先完成首个邮箱绑定流程，才能使用上述邮箱相关操作。
5. 验证码的有效期、发送频率、尝试次数、同一邮箱冷却期和防滥用策略由后续安全设计定义。

## 备选方案

### 仅校验邮箱格式即可使用

拒绝。不能证明邮箱控制权，允许用户占用他人邮箱并使密码重置渠道不可信。

### 以第三方平台返回的邮箱视为已验证

拒绝。不同提供方对邮箱声明和验证状态的语义不一致，且部分渠道不提供邮箱；NexaRAG 需要独立、统一的邮箱控制权证明。

### 仅在密码重置时验证邮箱

拒绝。会使未验证邮箱在登录与设置密码流程中提前成为不可信的身份标识。

## 后果

- 邮箱认证需要独立的验证码挑战状态，且验证码不得以明文形式持久化或记录到日志。
- 邮箱验证码发送与校验接口必须提供限流、防枚举和防暴力尝试措施。
- 设置本地密码、重置密码和邮箱绑定流程都需显式检查邮箱验证状态。
