# ADR：知识库按租户隔离，并为组织内共享保留边界

## 状态

已接受。

## 背景

当前系统只有全局 `document` 及其处理、分块和检索链路。文档没有知识库归属，列表、详情和检索也无法按业务边界区分文档。项目当前认证上下文只提供 `userId`，尚未提供租户或组织成员关系。

需要新增知识库概念，使文档能够按组织管理，并避免未来组织内共享时破坏既有数据归属与检索隔离。

## 决策

1. 引入独立的知识库实体；每个知识库必须归属且只归属一个租户。
2. 每份文档必须归属且只归属一个知识库；文档通过知识库间接归属租户，不将租户归属仅作为调用方约定。
3. 所有知识库、文档、分块、处理任务和检索读取操作都必须在请求的租户范围内校验归属。检索结果不得跨租户返回。
4. 知识库的组织内共享是目标能力，但成员身份、角色、授权策略以及跨知识库授权模型尚未确定；本决策不预设其具体实现。

## 备选方案

### 继续使用全局文档表，以调用参数区分知识库

拒绝。缺少持久化归属、查询约束和检索过滤，无法保证数据隔离，也无法支撑知识库生命周期管理。

### 文档直接记录 `tenantId`，不创建知识库实体

拒绝。只能提供租户级文档池，无法表达一个租户下多个知识库的管理、配置和共享边界。

### 按用户创建个人知识库

拒绝。用户已确认以租户/组织作为隔离边界，并且未来需要在组织内共享。

## 后果

- 身份上下文需要能可靠提供当前 `tenantId`，并在知识库与文档接口中参与鉴权与查询过滤。
- 数据迁移需要为存量文档建立明确的默认知识库和租户归属；未能确定归属的记录不得静默暴露给任意租户。
- 文档上传、外部文档导入、列表、详情、删除、重试和检索请求都需要显式或由路由上下文确定目标知识库。
- 索引元数据与检索过滤需要保留知识库、租户边界，避免仅依赖应用层事后过滤。
- 后续权限 ADR 将定义组织成员、角色和知识库共享规则。
