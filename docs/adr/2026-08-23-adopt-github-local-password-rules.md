# ADR：本地密码采用 GitHub 长度规则，泄漏密码检测暂缓

## 状态

已接受。

## 背景

NexaRAG 支持设置、重置和使用本地密码登录，但此前没有明确的密码验收规则。用户已要求密码标准与 GitHub 保持一致。

GitHub 当前要求密码至少为“8 位且包含数字与小写字母”或“15 位任意字符组合”，并在创建、登录和修改密码时使用包括 Have I Been Pwned 在内的数据集检查弱密码，且不明文存储输入的密码。 [GitHub 强密码说明](https://docs.github.com/en/authentication/keeping-your-account-and-data-secure/creating-a-strong-password)

用户确认一期暂不接入泄漏密码或弱密码数据集检测，因此一期仅采纳上述长度与字符组合规则；这是相对于 GitHub 完整策略的明确范围收缩。

## 决策

1. 本地密码必须满足以下任一规则：至少 15 位；或至少 8 位且同时包含至少一个 ASCII 小写字母与至少一个 ASCII 数字。
2. 不强制特殊字符或大写字母；用户可使用符合长度要求的密码短语。
3. 一期在设置、重置或登录本地密码时不执行已知弱密码/泄漏密码数据集检测；不得以假数据或不可靠的本地列表替代该能力。
4. 密码长度和组合规则由服务端统一实现；前端只提供即时提示，不能替代服务端校验。
5. 密码哈希算法、参数和最大接收长度由独立安全决策定义；泄漏密码检测的数据源与隐私保护调用方式留待后续安全迭代决定。

## 备选方案

### 仅要求八位长度

拒绝。无法达到 GitHub 对任意字符密码的更高长度门槛，也不利于使用密码短语。

### 强制大写、小写、数字和特殊字符四类组合

拒绝。与 GitHub 规则不一致，且会降低长密码短语的可用性而不必然提升抗猜测能力。

### 一期接入泄漏密码检测

暂缓。用户明确暂不将外部泄漏密码数据集或本地同步库纳入一期范围；后续接入时需单独评审数据源、可用性失败策略和隐私边界。

## 后果

- 所有本地密码入口必须复用同一密码策略服务，并将策略拒绝映射为不泄露具体敏感信息的业务响应。
- 一期仍不得将完整密码写入日志、指标、异常消息或第三方服务；未来增加泄漏密码检测时，必须先完成隐私保护设计。
- 密码策略变更后，既有密码不应被静默改写；是否在下一次登录或修改密码时强制升级，需另行决定。
