# ADR：使用 Redis 保存流式事件恢复缓冲

## 背景

自动恢复 SSE 流需要读取生成任务缺失的事件。进程内内存缓存无法支持负载均衡后的任意实例重连，也不能在单实例故障后继续恢复。现有生成取消协调已经使用 Redis 管理跨实例任务信息。

## 决策

以 Redis 作为运行中生成任务的短期、有序事件缓冲。事件按 `generationId` 分区并带过期时间保存；恢复请求由任意实例校验任务所属用户后，根据 `lastEventVersion` 读取缺失事件并继续订阅后续实时事件。

Redis 缓冲仅用于实时恢复，不替代助手消息终态的数据库快照。

## 备选方案

1. 每个应用实例使用内存事件缓冲，并依赖会话粘性。
2. 持久化所有高频流事件到数据库。
3. 断线后不支持恢复。

## 理由

Redis 已是现有跨实例生成协调的基础设施。短期缓存能够支持多实例容错和按版本补发，避免数据库承受 token 级写入压力。

## 后果

- Redis 键、过期时间、最大事件数和最大事件负载必须可配置并受限。
- 恢复读取必须校验 `generationId` 的任务归属。
- Redis 缓冲不可用时，前端进入“连接中断，任务仍在后台执行”降级态，最终通过数据库历史恢复。
