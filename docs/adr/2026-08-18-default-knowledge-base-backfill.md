# ADR：存量文档迁移至默认知识库

## 状态

已被 ADR：空环境切换至知识库模型取代。

## 背景

现有 `document` 已有真实文档、分块、任务及索引数据，但缺少知识库归属。新增知识库模型后，历史数据必须获得明确、可验证的归属，不能因空外键落入全局可见或不可检索状态。

## 决策

1. 数据迁移初始化内建默认租户及其默认知识库。
2. 所有未逻辑删除的存量 `document` 记录回填该默认知识库标识。
3. 文档分块、章节、处理任务、Outbox 与索引记录继续通过 `documentId` 关联文档，不重复回填知识库外键；读取及检索通过文档归属验证知识库范围。
4. 新文档必须在创建时确定知识库归属，不允许写入无知识库归属的文档。

## 备选方案

### 保留历史文档为“未分类”状态

拒绝。会形成特殊查询与鉴权分支，且无法保证历史文档不会跨知识库混入检索结果。

### 为每份历史文档新建一个知识库

拒绝。会制造大量无业务含义的容器，并破坏当前单一文档池的使用预期。

### 删除历史文档后重新导入

拒绝。会丢失现有处理状态、索引、审计信息与用户数据。

## 后果

- 迁移必须具备幂等性：重复执行不得重复创建默认租户、默认知识库或覆盖已存在的文档归属。
- 默认知识库初始化及文档回填必须在数据库迁移中完成，并对异常空归属数据提供可观测的校验或失败信号。
- 后续多租户认证启用后，默认租户中的历史文档仍只对该租户可见。
