# ADR：路由标识变更时级联迁移治理配置

## 背景

路由通过稳定的 `routeId` 管理，但路由级治理配置通过 `routeKey` 绑定。路由标识允许修改；若只更新 `model_route.route_key`，原路由级治理配置仍保留旧 key，运行时将无法匹配。

模型注册表以内存快照提供路由和治理配置，集群通过 Pub/Sub 接收版本变更后重建快照。

## 决策

当 `routeKey` 变更时，在同一数据库事务内：

1. 更新模型路由的 `routeKey`。
2. 将同一旧 key 对应的路由级治理配置迁移到新 key。
3. 递增一次模型注册表版本，并在事务成功提交后发布一次刷新消息。

刷新后的快照必须同时包含新的路由标识和新的路由级治理配置索引，不能保留旧 key 的有效配置。

## 备选方案

1. 存在路由级治理配置时禁止修改 `routeKey`。
2. 只更新路由，不迁移治理配置。
3. 通过两个独立事务分别更新路由和治理配置。

## 理由

级联迁移保留管理员已保存的路由策略，并以一个事务保证持久化一致性。只在提交成功后通知各实例刷新，可避免其他实例读到尚未提交或部分完成的数据。

## 后果

- 路由更新服务需要依赖治理配置服务或 Mapper 的受控迁移能力。
- 一次路由改名只发布一次注册表刷新消息，避免同一变更造成重复刷新。
- 需要为改名前后治理配置和刷新次数添加回归测试。
