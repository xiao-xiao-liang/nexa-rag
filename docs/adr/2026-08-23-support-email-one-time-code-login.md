# ADR：当前已验证邮箱支持一次性验证码登录

## 状态

已接受。

## 背景

NexaRAG 支持账号密码、邮箱密码和多种第三方登录。用户确认邮箱验证码除验证邮箱、更换邮箱和设置/重置密码外，也可直接完成无密码登录。

验证码若不区分用途、目标账号和消费状态，可能被跨流程复用或重放，进而扩大敏感操作的风险。

## 决策

1. 当前已验证邮箱可通过一次性验证码直接登录，无需本地密码。
2. 邮箱验证码可用于登录、验证邮箱、设置密码、重置密码和更换邮箱，但服务端必须为每种用途建立独立挑战并校验用途匹配。
3. 登录验证码只能为当前生效的已验证邮箱签发和消费；已被邮箱更换撤销的旧邮箱不得用于验证码登录。
4. 每个验证码必须有短时有效期、单次消费语义和服务端防重放校验；不得将验证码明文写入持久化存储或日志。
5. 邮箱验证码登录成功时，除建立新的 Sa-Token 登录态外，还必须为该新会话建立 15 分钟的最近验证授权；该授权不得跨会话复用，且不能替代更换邮箱的旧、新邮箱独立验码或密码重置流程。

## 备选方案

### 邮箱验证码只用于密码恢复，不支持登录

拒绝。不满足已确认的无密码邮箱登录方式。

### 一个验证码可跨用途复用

拒绝。登录验证码不应自动授权密码重置或邮箱变更等更高风险操作。

### 允许旧邮箱在更换后继续接收登录验证码

拒绝。与旧邮箱立即失效的既定邮箱更换规则冲突。

## 后果

- 验证码挑战记录需包含邮箱、用途、状态、过期时间和消费信息，并使用服务端原子操作完成校验与消费。
- 发送和验证端点应分别限流、统一返回抗枚举的响应，并审计敏感用途。
- 邮箱验证码登录是可用登录凭据，参与最后凭据保护的可登录性判断。
- 登录成功创建的最近验证授权与登录验证码一并由服务端原子消费和签发；若会话建立失败，不得留下可用的最近验证授权。
