# ADR：知识库名称在租户内唯一

## 状态

已接受。

## 背景

知识库会出现在列表、选择器、审计和检索范围中。若允许同一租户内存在同名知识库，用户和调用方难以正确辨识目标资源，且会增加删除、上传与检索范围配置的误操作风险。

## 决策

1. 同一租户内的未逻辑删除知识库名称必须唯一。
2. 唯一性必须由数据库约束兜底，并在创建和更新接口中转换为明确的业务冲突响应。
3. 不同租户可以创建同名知识库。
4. 名称规范化规则（例如前后空白、大小写与 Unicode 等价性）必须在接口校验与唯一索引策略中保持一致；具体规范在实现设计中明确。

## 备选方案

### 允许租户内同名

拒绝。会降低选择器和运维审计的可辨识性，并提高资源误操作风险。

### 全局唯一

拒绝。不符合租户隔离边界，会让互不相关的组织相互占用名称。

### 仅在服务层查询后校验

拒绝。并发创建或更新会绕过查询校验，必须由数据库唯一约束保证最终正确性。

## 后果

- 迁移需建立包含租户与有效删除状态的唯一约束，并评估目标数据库对逻辑删除场景的索引行为。
- 创建、更新和并发测试需要覆盖同租户冲突、跨租户同名及逻辑删除后的名称复用。
- 默认知识库名称须与其他初始化数据一起保证幂等创建。
