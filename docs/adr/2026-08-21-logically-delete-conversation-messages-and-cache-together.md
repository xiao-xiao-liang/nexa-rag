# ADR：删除会话时级联逻辑删除消息并清除缓存

## 背景

会话和消息是用户可见历史的同一生命周期。若仅隐藏会话记录而保留可查询消息，或仅删除数据库记录而遗留 Redis 上下文缓存，会造成数据可见性不一致、缓存回源错误或后续恢复语义不清。

## 决策

用户删除会话时，在同一业务操作中：

1. 将 `chat_conversation` 标记为逻辑删除；
2. 将该 `conversationId` 下的全部 `chat_message` 标记为逻辑删除；
3. 将该用户和会话对应的 Redis 会话上下文缓存删除。

查询会话、查询历史消息、构建 LLM 上下文和读取缓存均不得返回逻辑删除数据。删除后不立即物理删除数据库记录。

## 备选方案

1. 仅将会话标记为删除，保留消息原有可查询状态。
2. 立即物理删除会话、消息和缓存。
3. 仅在会话列表中隐藏记录，不改变持久化数据。

## 理由

级联逻辑删除使会话与消息保持同一用户可见性，并保留受控恢复或审计空间。同步清除 Redis 防止已删除会话仍以缓存形式参与后续上下文读取。

## 后果

- 删除流程需要以 `userId + conversationId` 为范围校验归属后执行消息批量逻辑删除。
- MySQL 语句、历史接口、上下文重建和缓存键均需统一过滤或清除已删除数据。
- 后续如需要物理清理，应通过独立的保留期任务处理，而不能改变用户删除接口的同步语义。
- 正在生成的会话删除行为需单独定义，避免生成任务在删除后再次写入消息或缓存。
