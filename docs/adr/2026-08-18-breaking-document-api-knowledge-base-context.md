# ADR：文档接口改为强制携带知识库上下文，不保留全局接口兼容层

## 状态

已接受。

## 背景

现有文档接口以全局 `documentId` 或无范围的列表、上传入口工作，无法表达或校验文档所属知识库。保留旧接口作为隐式默认知识库兼容层，会长期形成绕过知识库归属校验的入口，并使后续多租户接入时难以清理。

## 决策

1. 不兼容现有全局文档 API；所有文档列表、创建、上传、外部导入、详情、处理、重试、删除、状态、分块及检索相关调用均必须携带知识库上下文。
2. 不为旧的 `GET /api/documents`、`POST /api/documents`、`POST /api/documents/upload` 及基于裸 `documentId` 的资源操作保留隐式默认知识库回退。
3. 前端、集成调用方和测试在同一交付中迁移到新契约。
4. 知识库标识采用嵌套资源路径表达。文档集合入口为 `/api/knowledge-bases/{knowledgeBaseId}/documents`，文档子资源在该路径下继续以 `{documentId}` 定位；无论资源层级如何，服务端都必须验证文档归属该知识库。

## 备选方案

### 保留旧全局接口并自动映射至默认知识库

拒绝。会让调用方继续依赖无范围访问，并使默认知识库成为无法移除的隐式兼容机制。

### 为旧接口提供一段时间的弃用期

拒绝。本期可同步改造调用方，兼容层的收益不足以抵消鉴权和测试复杂度。

## 后果

- 此变更是破坏性 API 变更；需要同步修改前端 API 客户端、控制器测试、集成测试及接口文档。
- 服务器必须将路径/参数中的知识库标识视为待验证输入，不能仅依赖客户端传递。
- 文档资源操作须同时验证当前租户、知识库归属和文档归属三层边界。
- 控制器、前端路由和 API 客户端需要以知识库作为文档操作的父资源；裸 `documentId` 不能构成可访问的资源地址。
