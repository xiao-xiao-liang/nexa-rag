# ADR：在用户表保存一期唯一全局角色

## 状态

已接受。

## 背景

一期只有 `ADMIN` 与 `USER`，无在线角色委派，且每个用户只允许拥有一个全局角色。用户—角色关联表在当前约束下不提供额外表达能力。

## 决策

1. `auth_user.role_id` 直接关联 `auth_role`，每个用户只有一个全局角色。
2. 保留 `auth_role`、`auth_permission` 与 `auth_role_permission`，继续以权限码保护 `/api/model/**`。
3. 默认管理员的 `role_id` 为 `ADMIN`；新注册用户的 `role_id` 为 `USER`。
4. 将来支持多角色时再新增用户—角色关联表及数据迁移；一期不提前保留空关联表。

## 后果

- 当前角色读取只需查询用户、角色与角色权限，减少一次关联查询和一张表。
- 后续扩展多角色需要显式迁移，不得将多个 roleId 拼接写入用户字段。
