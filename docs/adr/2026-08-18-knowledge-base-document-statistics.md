# ADR：知识库接口返回服务端文档状态统计

## 状态

已接受。

## 背景

知识库页面需要展示其文档规模与处理概况。当前文档列表分页返回，前端无法从单页数据准确计算全库统计；跨页遍历既不可靠也会造成额外请求。

## 决策

1. 知识库分页列表和详情返回当前知识库的真实文档统计：未删除文档总数、待处理数、处理中数、已索引数、失败数。
2. 聚合必须由服务端在当前租户及知识库边界内计算；不得混入其他知识库或逻辑删除文档。
3. 统计是读取时的聚合快照，不承诺与并发处理中的文档状态强一致；返回数据需能表达其当前查询时刻。
4. `UPLOADED` 仅计入总数与待处理数，不计入处理中、已索引或失败。处理中覆盖已进入处理流水线但尚未进入终态的状态；`INDEXED` 与 `FAILED` 分别计入已索引和失败统计。

## 备选方案

### 前端遍历文档分页后自行统计

拒绝。无法保证完整性和一致性，并会放大网络与服务端负载。

### 只返回文档总数

拒绝。无法支撑知识库处理健康度的基本展示与运维判断。

### 在知识库表中维护计数器

暂不采用。处理流水线状态迁移频繁，计数器需要额外的事务与补偿机制；首期优先使用可验证的查询聚合，并根据性能数据决定是否物化。

## 后果

- 文档表需要以知识库归属、逻辑删除和状态支持聚合查询的索引。
- 知识库 VO、接口测试及前端展示需要包含五项统计字段。
- 状态机新增状态时必须评估其属于“处理中”、终态还是未开始，以免统计语义漂移。
