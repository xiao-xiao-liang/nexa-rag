# ADR：账号一期使用启用与禁用状态

## 状态

已接受。

## 背景

账号需要有一个统一的生命周期开关，以处理安全事件、滥用处置和运维止损。仅删除密码、邮箱或第三方身份不能覆盖所有登录方式，也不能确保既有 Sa-Token 会话立即失效。

## 决策

1. 账号实体一期仅使用 `ACTIVE` 与 `DISABLED` 两种状态；新建账号默认 `ACTIVE`。
2. `DISABLED` 账号必须立即撤销全部 Sa-Token 会话，并拒绝账号密码、邮箱密码、邮箱验证码、QQ、飞书、Google 和 GitHub 的新登录或新会话建立。
3. 禁用检查是认证与授权的统一前置条件；不得仅依赖前端隐藏入口或仅在某一种登录方式中检查。
4. 对外响应继续采用防枚举的通用认证失败语义，不向未认证客户端暴露账号是否被禁用；安全审计记录实际拒绝原因。
5. 受控运维可将 `DISABLED` 账号重新启用为 `ACTIVE`；重新启用不恢复任何已撤销会话、最近验证授权或验证码挑战，用户必须重新登录。
6. 一期不提供管理员角色、禁用管理后台或用户自助删除账号界面；账号状态变更仅保留给受控运维入口，并必须写入安全审计日志。

## 备选方案

### 仅删除或清空本地密码

拒绝。邮箱验证码和已绑定第三方身份仍可登录，且不能撤销既有会话。

### 每种登录入口单独维护封禁逻辑

拒绝。容易遗漏新增认证方式，导致禁用状态被绕过；应在统一认证与授权链路中执行。

### 一期实现完整管理员账号管理后台

拒绝。一期尚未引入 RBAC 与管理员权限模型，直接提供后台会扩大授权面；先保留受控运维能力。

### 重新启用后恢复旧登录会话

拒绝。禁用通常用于安全止损；恢复旧会话会重新激活可能被盗用的凭据。重新启用后必须重新认证建立新会话。

## 后果

- 账号数据模型、登录状态建立、会话刷新、敏感操作和业务鉴权均需检查账号状态。
- 禁用操作与账号级会话撤销必须具备一致性；并发请求在禁用完成后不得继续延长已撤销会话。
- 重新启用、禁用与会话撤销均须记录操作者、目标 `accountId`、原因（如有）和时间；不得记录会话 Token、密码或验证码。
- 后续若增加账号删除、冻结期限、申诉或 RBAC，应以此状态模型为基础扩展，不得复用可变账号名或登录凭据代替账号状态。
