# ADR：通过已验证邮箱激活默认管理员账号

## 状态

已接受。

## 背景

原固定开发用户的历史业务数据需要安全迁移至默认管理员账号。不能把管理员权限交给首个普通注册者，也不能在代码、数据库迁移或日志中写入初始密码。

## 决策

1. 部署配置仅预置默认管理员的账号名和邮箱地址；该配置属于受控运行环境，不提交仓库。
2. 系统初始化时创建或保留默认管理员对应的 `userId`、`accountId` 与 `ADMIN` 角色，并将原固定业务 `userId=864019719617777664` 的历史数据映射到该用户。
3. 默认管理员初始没有可用密码、会话或第三方身份；只有持有预置邮箱并完成邮箱验证码验证的人，才能执行该保留账号的首次激活与密码设置。
4. 首次激活成功后才使该账号可完成普通登录并使用管理员接口；激活过程与邮件验证码挑战均需审计。
5. 首次激活不得走普通自助注册而新建另一个用户或账号，也不得允许客户端覆盖部署预置的邮箱、账号名、角色或历史数据归属。

## 备选方案

### 首个注册账号自动成为管理员

拒绝。公开注册时序不可信，也会导致历史业务数据错误归属。

### 预置明文或固定初始密码

拒绝。密码易泄漏且难以安全轮换，不符合当前无初始密码和邮箱验证策略。

### 仅通过直接数据库手工插入管理员

拒绝。容易遗漏 `userId`、`accountId`、历史数据映射和审计关系，且不可重复验证。

## 后果

- 部署文档和环境配置需定义默认管理员账号名、邮箱及初始化开关，但不得包含密码、验证码或第三方密钥。
- 初始化实现必须可幂等；重复启动不得新建多个管理员账号、覆盖已激活凭据或重复迁移历史数据。
- 若预置邮箱输入错误，应由受控运维修正配置并执行受审计的恢复流程，普通注册或 API 调用不得抢占管理员身份。
