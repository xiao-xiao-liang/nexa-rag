# ADR：工具完成后再流式输出主 Markdown

## 背景

目标回答区将工具运行卡置于主 Markdown 正文之前。若模型正文和后续工具调用交错输出，前端需要在已经流出的正文前插入或更新工具卡，阅读顺序与界面结构都会变得不稳定。

## 决策

一期采用工具优先输出。工作流先完成本轮计划内工具调用并使每个工具进入成功、失败或取消终态；之后才开始向前端推送主 Markdown 正文增量。工具运行卡在本轮助手消息中始终位于 Markdown Root 之前。

工具失败达到重试上限后仍可进入正文生成阶段，模型基于已有上下文和受控失败事实完成回答。

## 备选方案

1. 允许工具调用与 Markdown 正文任意交错。
2. 先输出 Markdown，再在末尾附加工具记录。

## 理由

工具优先输出与目标交互一致，前端消息结构稳定，Markdown 流式渲染无需因后续工具操作重排。

## 后果

- 首个正文 token 必须等待工具阶段结束；工具进度卡用于向用户反馈等待状态。
- 工作流需明确区分工具执行阶段与回答生成阶段。
- 将来若需要边生成边调用工具，必须另行设计可交错的消息块排序与用户体验。
