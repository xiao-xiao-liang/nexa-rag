# ADR：按增量阈值异步生成会话摘要

## 背景

会话摘要能够限制送入模型的历史上下文，但摘要本身需要额外模型调用。若在当前回答链路同步执行，首 token 和回答完成时间都会增加；若每轮回答都生成摘要，则会引入不必要的模型成本和数据库读取。

## 决策

会话摘要仅在当前回答进入终态后异步调度，摘要失败不得影响已完成回答。仅当自最新摘要覆盖位置起累计的新用户消息轮次达到增量摘要阈值时，才生成下一版摘要。

阈值由配置提供，初始值为 8 个新增用户轮次；摘要仍是可从原始消息重建的派生数据。

## 备选方案

1. 在每轮回答前或回答后同步生成摘要。
2. 每轮回答完成后都异步生成摘要。
3. 完全不生成摘要，只按固定数量截取最近消息。

## 理由

异步、按阈值触发能将摘要的延迟和失败与用户当前回答隔离，并控制模型调用频率；原始消息持续保留，允许在摘要质量问题或策略调整后重新生成。

## 后果

- 摘要调度必须可观测且受并发控制，失败仅记录并保留上一版本。
- 摘要覆盖位置应支持准确定位增量范围，避免长会话反复扫描或重复总结相同消息。
- 阈值初始值为 8；后续变更会影响成本、上下文质量和摘要时效，需要通过配置和指标校准。
