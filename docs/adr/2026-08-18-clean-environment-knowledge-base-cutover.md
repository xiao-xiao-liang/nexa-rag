# ADR：以空数据环境切换至知识库模型

## 状态

已接受。

## 背景

原计划为存量文档回填默认知识库并重建检索索引。但当前数据库、Elasticsearch 和 Milvus 中的数据均无业务保留价值，且由用户在发布前统一清空。保留历史迁移和索引重建逻辑会增加无意义的复杂性与错误面。

## 决策

1. 用户负责在切换前清空数据库、Elasticsearch 与 Milvus 的既有数据；本次实现不执行任何清理命令或自动删除逻辑。
2. 数据库迁移仅创建/演进表结构，并幂等初始化内建默认租户与受保护默认知识库。
3. 不实施历史 `document` 回填，不实施历史向量、关键词或章节索引重建。
4. 新上传或导入的文档从创建开始写入知识库、租户索引元数据；所有检索均立即强制按该元数据过滤。
5. 本 ADR 取代“存量文档迁移至默认知识库”中的回填实施决策；默认知识库的定义与保护规则仍然有效。

## 备选方案

### 清空环境后仍保留历史回填和重建任务

拒绝。没有待迁移的数据，任务只会增加部署复杂度和潜在故障。

### 在应用启动时自动清空数据库或外部索引

拒绝。清理是不可逆的环境操作，必须由用户在明确授权和受控流程中执行，不能成为应用行为。

## 后果

- 上线前必须完成外部数据清空与环境验收；否则旧索引不会被新检索范围识别。
- 本次 Flyway 迁移和应用代码无需承担历史数据兼容性。
- 后续若在有保留数据的环境启用该能力，必须重新设计数据迁移与索引重建方案。
