# ADR：登录态采用三天滑动有效期，不设独立闲置超时

## 状态

已接受。

## 背景

NexaRAG 已决定允许同一账号多设备并发登录，仍需定义单个 Sa-Token 登录态的有效期与续期规则，以平衡重复登录频率和失窃 Token 的暴露时间。

## 决策

1. 每个 Sa-Token 登录态初始有效期为三天。
2. 登录态在到期前发生有效业务操作时，服务端将其有效期重新延长三天，形成滑动有效期。
3. 不配置独立于该三天滑动窗口之外的闲置超时；只要用户持续在每个三天窗口内操作，登录态可持续有效。
4. 登出、账号级会话撤销和 Token 无效化仍可随时提前终止登录态，不受滑动续期影响。

## 备选方案

### 固定三天绝对过期

拒绝。持续活跃用户仍需定期被迫重新登录，与已确认的“操作即续期”体验不符。

### 额外配置更短闲置超时

拒绝。用户明确不设置独立的连续无操作过期窗口。

### 永久登录态

拒绝。无法限制 Token 长期泄露后的可用时间。

## 后果

- Sa-Token 配置和请求认证链需要安全地续期当前 Token，避免无认证请求或静态资源请求无条件延长会话。
- 需要定义哪些请求构成有效业务操作；健康检查、预检、静态资源与认证失败请求不得续期。
- 前端在 Token 到期收到未认证响应后应清理本地状态并跳转登录页。
