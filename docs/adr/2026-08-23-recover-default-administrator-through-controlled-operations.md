# ADR：通过受控部署运维恢复默认管理员

## 状态

已接受。

## 背景

一期仅有一个不可委派的默认管理员。若其邮箱失控、账号被禁用或凭据泄露，系统需要可恢复性；但不应以此为由开放普通角色管理 API 或后台。

## 决策

1. 默认管理员不可用时，允许部署级受控运维执行紧急恢复或替换管理员。
2. 恢复流程不提供公开 HTTP API、前端界面或普通管理员自助入口；仅能在受控部署环境中按运维步骤执行。
3. 恢复或替换必须撤销原管理员的全部会话、最近验证授权、验证码挑战和可用登录凭据，并保留原账号、用户及审计历史以维持追溯性。
4. 替换后的默认管理员仍须通过其部署预置邮箱验证码完成首次激活；不得配置或输出初始密码。
5. 每次恢复应记录触发人、审批/工单标识（如有）、原/新 `userId` 和 `accountId`、原因、时间及结果；不得记录密码、验证码、Token 或完整邮箱地址。

## 备选方案

### 不提供任何恢复路径

拒绝。单一管理员失联会使模型网关和提示词管理永久不可操作，且无法安全处置失陷账号。

### 提供公开的“找回管理员”接口

拒绝。该接口本身将成为最高权限提权入口，难以在一期安全维护。

### 让现有管理员在线授予继任者

拒绝。一期明确不提供角色委派；在线操作也无法解决管理员已不可用的场景。

## 后果

- 运维文档需明确恢复前检查、执行授权、会话撤销、邮箱验证和审计核验步骤。
- 后续引入多管理员或完整 RBAC 时，可以将该受控流程演进为带审批的角色治理能力，但不得削弱现有审计和凭据撤销要求。
