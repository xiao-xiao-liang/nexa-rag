# ADR：同一会话只允许一条活动生成

## 背景

一条助手生成会同时产生 Markdown 正文增量、工具操作状态和事件版本。若同一会话允许多条任务并发生成，历史消息顺序、取消目标、SSE 恢复和工具运行卡归属都会出现歧义。

## 决策

同一会话任意时刻最多存在一条 `RUNNING` 生成任务。前端在生成期间禁用新的发送操作；后端也必须按会话边界拒绝第二个生成请求，直到当前任务进入完成、失败或取消终态。

## 备选方案

1. 允许同一会话多条生成并发，并用生成任务标识独立管理。
2. 仅由前端禁用发送，不在后端建立并发约束。

## 理由

单活动生成与当前交互一致，能保证消息顺序、工具卡、取消与断线恢复都有唯一归属。后端约束防止多标签页或直接调用接口绕过前端限制。

## 后果

- 生成创建必须具备会话级并发保护，并在终态后释放。
- 前端收到“已有活动生成”时应展示明确提示并保持当前回答可见。
- 同一用户仍可在不同会话中分别进行生成。
