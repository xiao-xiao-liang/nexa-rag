# ADR：采用服务端校验的结论级引用标记

## 背景

产品要求用户能够在回答的每个具体结论后，通过可点击的 `[1]`、`[2]` 查看所依据的文档分块。现有工作流会在证据质量节点产出已接纳的 `RetrievalChunk`，而助手消息、流式事件和前端消息类型尚未传递或展示引用。

仅在回答末尾展示检索过的文档，无法说明某个结论与哪条证据对应；直接信任模型输出的编号又会出现不存在、超出本轮范围或未经校验的引用。

## 决策

1. 服务端以本轮 `acceptedEvidenceResults` 的稳定顺序构造 `Citation` 列表，并分配从 `1` 开始的 `citationId`；模型提示词中的每段证据均携带对应编号。
2. 模型输出使用受限的 Markdown 标记 `[n]`，紧随其支持的结论，不在参考列表、代码块或普通文本中模拟引用标记。无法给出证据编号的具体结论必须紧随 `【未提供引用】`；该标记在同一次 Markdown 流中输出。
3. 服务端在落库和发出完成事件前解析引用标记：仅允许映射到当前 `Citation` 列表的正整数；无效编号降级显示为“未提供引用”并记录可观测告警。服务端不根据模型内容臆造缺失引用，也不因单个结论漏引而丢弃整轮回答。
4. 前端只把校验后的 `[n]` 渲染为可点击标记；点击后按当前用户权限加载相应文档分块的标题、章节和正文预览。引用失效或无权访问时显示不可用状态。
5. `referencesJson` 仍遵循非快照策略，只持久化可定位元数据、当时排序和分数，不保存分块正文。`Citation` 列表随完成、失败和取消的最终助手消息一起持久化；SSE 只在引用已稳定后发送快照，断线重放使用同一事件数据。
6. 不要求模型额外生成 JSON 或第二份结论结构；引用标记与 Markdown 正文在同一次流式模型调用中输出。服务端只校验已出现的标记，不通过额外模型调用或句子切分推断未标记结论。
7. 服务端在首个回答正文 token 前发送不可变的 `CITATIONS` SSE 事件，携带当前助手消息的 `Citation` 列表；`COMPLETE` 事件重带同一列表。前端收到 `CITATIONS` 后即可把后续正文中的有效 `[n]` 渲染为可点击标记，Redis 重放按事件版本恢复相同顺序。
8. 前端点击 `[n]` 时仅以 `messageId + citationId` 调用专用引用详情接口。服务端从该助手消息的引用清单定位文档和分块，并重新校验当前用户权限，返回“可预览”“已失效”或“无权查看”；前端不直接用文档或分块标识读取内容。
9. 引用详情以回答正文附近的轻量弹层展示，包含文档标题、章节定位和当前分块摘录，并提供“打开原文档”入口；不在聊天页面常驻右侧详情栏。
10. “打开原文档”由引用详情接口返回一次性、已授权的导航信息：站内上传文档进入站内预览，外部来源文档才跳转受控的 `sourceUrl`。浏览器不得直接使用数据库保存的原始文件 URL、对象名或外部 URL。
11. 引用清单继续存入 `chat_message.references_json`，不新建 `chat_message_citation` 表。当前引用仅以 `messageId + citationId` 查询，没有跨消息检索、统计或审计需求；JSON 内容仍不包含分块正文。
12. 回答提示词保留证据优先、证据不足、证据冲突和提示注入防护要求，并新增引用输出约束：每个可核验结论紧随服务端提供编号范围内的 `[n]`；无法给出证据编号的具体结论紧随 `【未提供引用】`；不得编造编号、文档标题、URL 或其他来源。
13. 完成、取消和失败的助手消息都保存同一引用清单；若保留的部分正文包含有效 `[n]`，历史与实时界面均继续展示和允许查看该引用。正文为空时不展示引用入口。

## 备选方案

1. 只在回答底部按文档列出来源。
2. 由前端将所有检索结果自动附加到回答末尾。
3. 允许模型自由输出文档标题或链接，不作结构化校验。
4. 在 Markdown 回答之外生成结论与引用的结构化结果。

## 理由

结论级标记满足可核验交互；引用清单由服务端从已接纳证据生成，避免把原始召回、被重排淘汰的候选或模型臆造的来源暴露给用户。非快照持久化复用既有数据生命周期决策。单次 Markdown 流保持当前首 token 时延和传输形态，避免重复输出造成的 token 与时延成本。

## 后果

- 提示词、回答 Markdown 解析器、SSE 事件和历史消息投影必须新增兼容的结构化 `citations` 字段。
- 引用编号只在单条助手消息内有效，历史消息加载时不得与其他消息合并编号。
- 首个正文 token 之前增加一个小型 `CITATIONS` SSE 事件；该事件的清单在本次生成中不可变，完成事件重复携带以便前端最终对账。
- 模型仍可能遗漏对某些结论的标记；单个结论的无效编号会降级为“未提供引用”。对于完全没有标记的结论，系统不做猜测性句子切分；需要由模型在同一次输出中显式标记，或接受该限制。
- `【未提供引用】` 是模型的显式声明，前端只负责提示而不将其转为可点击来源。
- 文档变更后，引用打开的是当前可访问的分块版本；若不可用，前端明确标记失效。
- 引用详情接口以助手消息和引用编号作为边界，避免历史消息中的内部文档、分块标识成为越权读取入口。
- 同一回答可包含多个引用；再次点击编号时切换弹层内容，阅读回答的可用宽度不因引用详情而永久收窄。
- 原文档打开动作沿用引用详情的当前权限校验，文件地址与外部地址都不作为历史消息或 SSE 的直接字段下发。
- 现有 `references_json` 字段必须定义版本化、可向后兼容的 JSON 结构；旧消息的空值或旧格式视为“无可用引用”。
- 引用语法是回答提示词的输出契约；服务端仍须校验模型输出，提示词本身不是安全边界。
- 取消或失败不回滚已生成正文及其可核验引用；引用详情仍按当前权限和失效规则读取。
