# ADR：助手消息持久化工具操作快照

## 背景

智能体回答区需要同时展示 Markdown 正文和工具运行卡。SSE 连接中的工具状态仅存在于当前浏览器内存时，页面刷新、重新进入会话或跨设备访问都会丢失工具调用记录，历史回答无法还原为生成时的用户可见状态。

## 决策

助手消息在生成进入完成、失败或取消终态时，持久化最终 Markdown 正文和可展示工具操作快照。历史消息接口返回该快照，使前端能够恢复工具运行卡及其终态，而无需重放过去的 SSE 连接。

SSE 仍用于实时传输模型正文增量和工具状态变化；它不是历史消息的唯一事实来源。临时 token 事件不作为逐条历史事件持久化。

## 备选方案

1. 仅持久化 Markdown 正文，工具卡只在当前流式页面展示。
2. 持久化每一条 SSE/token 事件，并由前端从头重放。
3. 仅由浏览器本地缓存工具操作，刷新后不恢复。

## 理由

最终快照可以恢复用户实际看到的工具运行结果，满足刷新与跨设备访问，同时避免存储大量高频 token 事件。前端只需按稳定操作标识渲染终态卡片，后端不必依赖某个旧 SSE 连接仍然可用。

## 后果

- 助手消息的数据模型和历史消息接口需要增加可展示工具操作快照。
- 实时流和历史快照必须使用稳定的 `generationId`、`messageId`、`processId` 与 `opId` 对应同一生成过程。
- 工具操作的展示字段需要在持久化前经过当前的可见性与数据脱敏策略处理。
- 页面刷新后展示最终快照；生成中断线恢复的实时补发策略另行设计。
