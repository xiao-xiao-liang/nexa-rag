# ADR：在服务端会话保存当前租户上下文

## 状态

已接受。

## 背景

用户加入企业租户后可同时拥有默认租户与一个或多个企业租户成员资格。业务资源访问需要唯一、可信的当前工作空间，不能把前端传入的 `tenantId` 直接作为授权事实。

## 决策

1. 新登录会话的当前租户初始化为该用户的默认租户。
2. 用户切换工作空间时，服务端以当前登录主体校验目标 `tenantId` 的有效成员资格；校验成功后才在当前 Sa-Token 会话的服务端状态中更新当前租户。
3. 业务接口从服务端会话解析当前 `tenantId`；请求体、查询参数、路径变量、Header、前端缓存中的 tenantId 均不得替代或覆盖该事实。
4. 租户切换、切换失败及成员资格校验失败必须记录可审计事件，但不记录会话 Token。

## 备选方案

### 每次请求由前端传 tenantId

拒绝。容易被篡改或遗漏成员资格校验，无法形成一致的数据隔离边界。

### 账号永久绑定单一租户

拒绝。已确认支持企业租户邀请，同一用户会同时拥有默认租户与企业租户资格。

### 每个租户分别登录

拒绝。将工作空间选择误建模为身份切换，增加凭据和会话管理复杂度。

## 后果

- 认证上下文需同时提供 `userId`、`accountId`、当前 `tenantId` 与角色/权限；每项均由服务端解析。
- 业务查询、异步任务和缓存键需使用当前可信租户范围，避免只按资源 ID 或客户端 tenantId 读取。
- 成员移除、租户禁用及会话撤销时对当前租户状态的处理需要另行明确。
