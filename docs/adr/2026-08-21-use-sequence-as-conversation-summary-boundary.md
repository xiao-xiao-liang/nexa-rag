# ADR：使用消息序号作为会话摘要覆盖边界

## 背景

会话摘要需要标识已覆盖的历史范围，以便只读取新增消息。仅保存最后一条消息 ID 时，服务需要先在已读取列表中定位该 ID；当会话很长、读取窗口受限或历史数据变化时，容易退化为重复读取和重复摘要，且无法直接利用消息游标索引完成增量查询。

## 决策

在 `chat_conversation_summary` 中新增 `summary_until_sequence`，表示该摘要覆盖的最后一条会话消息序号。增量摘要读取时按 `conversation_id`、`user_id` 和 `sequence > summary_until_sequence` 查询未覆盖消息，并以新的最后消息序号写入下一版摘要。

现有 `last_message_id` 在迁移期间保留以兼容已有摘要记录和展示需求，但不再作为增量查询的主边界。

## 备选方案

1. 继续只使用 `last_message_id` 并在内存列表中查找。
2. 每次读取完整会话历史后按时间或 ID 比较。
3. 删除旧摘要后从头重新生成。

## 理由

`sequence` 是会话内单调递增且已有索引支持的顺序字段。以它作边界可精确、直接地读取增量范围，降低长会话的数据库读取和摘要重复率。

## 后果

- 需要执行可兼容的数据库迁移，并为存量摘要回填覆盖序号或在回填完成前受控降级。
- 摘要领域对象、缓存快照和摘要服务须携带并维护该字段。
- 新的增量读取必须限制单次最大消息量，并在达到阈值后继续分批摘要，避免一次摘要请求负载过大。
