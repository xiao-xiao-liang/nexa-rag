# ADR：流式恢复失败时保留后台运行状态

## 背景

前端会在 SSE 断线后自动恢复流。恢复多次失败或服务端事件缓冲过期时，生成任务可能仍在后台继续运行。将消息直接标记失败会与后端真实状态不一致，并可能让用户误以为最终回答不会产生。

## 决策

流式恢复不能完成时，前端保留已收到的 Markdown 与工具运行卡，展示“连接中断，任务仍在后台执行”。该状态不改变后端生成任务，也不把助手消息标记为失败或取消。

后端生成进入终态后持久化最终完整回答与工具操作快照。用户刷新页面或重新请求历史消息接口时，以该最终快照替换前端临时展示状态；正常连接期间不使用轮询等待终态。

## 备选方案

1. 流式恢复失败后立即将助手消息标记为失败。
2. 继续无限自动重连。
3. 定时轮询消息历史，直到任务结束。

## 理由

后台任务仍可能成功完成，因此需要向用户准确表达连接状态与任务状态的区别。最终快照提供可靠恢复点，而无需把高频轮询引入正常流式路径。

## 后果

- 前端需要独立的恢复降级展示状态，不能复用 `FAILED` 或 `CANCELLED`。
- 历史消息接口必须能够返回已经持久化的完整终态快照。
- 生成任务最终写库失败时，后端应进入明确失败终态，而不是无限停留在运行中。
