# ADR：合并用户与账号持久化主体

## 状态

已接受。

## 背景

一期每个用户只拥有一个账号名、一个全局角色和一组登录凭据。此前 `userId` 与 `accountId` 严格一对一，两个主键用途重合，增加关联、查询和迁移复杂度。

## 决策

1. 仅保留不可变 `userId` 作为认证、授权和业务数据主体；不创建 `auth_account`，不保留 `accountId`。
2. `accountName`、规范化账号名、用户状态、默认租户和全局 `roleId` 均存储于 `auth_user`。
3. 用户状态使用 `TINYINT`：`0` 为启用（ACTIVE），`1` 为禁用（DISABLED）。
4. 不再在身份、凭据、会话、审计和授权表中使用 `accountId`；全部改以 `userId` 关联。
5. 不设置通用乐观锁 `version` 字段；对会并发变更的账号名、凭据、成员资格和邀请流程使用唯一约束、条件更新及 `SELECT ... FOR UPDATE` 保证一致性。

## 后果

- 现有业务 `user_id` 与认证主体直接一致，固定开发用户历史数据无需 user/account 映射。
- 账号名仍可变且立即释放，永远不能替代 `userId` 作为关联键。
- 未来若需要一人多账号，必须新增独立账号表和关系迁移；不得在一期模型上临时复用账号名。
