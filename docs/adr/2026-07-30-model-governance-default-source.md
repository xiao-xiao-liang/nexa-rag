# ADR：模型治理配置默认值的事实来源

## 背景

模型治理配置包含重试、熔断、限流、超时和并发隔离等多项字段。此前服务层在记录不存在时构造一份内存默认配置，并在创建时手动填充所有默认字段；数据库表同时已为这些字段定义了 `NOT NULL DEFAULT`。

两套默认值会产生重复维护，并可能因字段新增或数值调整而不一致。

## 决策

数据库表 `model_governance_config` 是持久化治理配置默认值的唯一事实来源。其默认值采用当前 CHAT 模型的治理策略基线，保持既有的新建 CHAT 模型与路由行为。

查询接口仅返回已保存的治理配置；不存在记录时不构造、不返回内存默认配置，并以成功响应中的 `data: null` 表示。首次创建仅写入绑定身份等必要业务字段，其余 CHAT 基线字段由数据库填充；创建成功后重新查询并返回完整配置。

Embedding 和 Rerank 模型沿用 CHAT 基线，仅在服务层写入相对基线不同的字段。

模型配置和模型路由在 `auto-create-default` 开启时，创建完成后自动持久化对应治理配置；该配置属于已保存配置。仅当自动创建关闭或历史数据缺失时，查询接口才返回 `data: null`。

## 备选方案

1. 在服务层和数据库中同时维护全量默认值。
2. 仅在服务层维护默认值，不使用数据库默认值。
3. 将数据库当前的默认关闭策略作为新的系统策略。
4. 保留未保存时返回内存默认配置的接口行为。

## 理由

数据库约束可覆盖所有写入入口，并通过 `NOT NULL DEFAULT` 防止持久化空值。以 CHAT 策略作为数据库基线能够保持既有运行行为；Embedding 和 Rerank 只写少量差异，避免重复维护全量字段。仅返回已保存记录使接口结果与数据库事实一致，避免前端将尚未创建的虚拟配置误认为已生效配置。

## 后果

- 首次保存后的完整响应需要回查数据库。
- 调用方需要将成功响应中的 `data: null` 识别为未保存配置，并与“已保存但全部开关关闭的配置”区分。
- 服务层不再维护 CHAT 基线的全量默认数值，仅维护 Embedding 和 Rerank 的差异值。
- 需要通过新的数据库迁移同步已部署环境的列默认值。
- 自动创建开启时，模型配置和模型路由创建事务会额外写入一条治理配置。
