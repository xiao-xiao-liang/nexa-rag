# ADR：统一邮箱一次性验证码有效期、尝试次数与限流策略

## 状态

已接受。

## 背景

邮箱验证码用于登录、邮箱验证、设置密码、重置密码、更换邮箱和二次验证。若各入口自行定义有效期、重发间隔或验证次数，将产生行为不一致，也难以统一防范枚举、暴力尝试和邮件轰炸。

## 决策

1. 所有邮箱验证码均为六位数字，服务端签发后五分钟有效。
2. 每个验证码挑战最多允许五次验证尝试；达到上限或超过有效期后必须作废。
3. 同一邮箱、同一用途的验证码再次发送间隔至少为 60 秒。
4. 同一邮箱跨全部验证码用途每天最多发送 10 次；自然日边界由服务端按 `Asia/Shanghai` 计算，不能使用客户端时间。
5. 验证码发送与验证均按邮箱和可信客户端 IP 限流；具体 IP 阈值由配置管理并根据运行监控调整。
6. 验证码挑战必须绑定邮箱、用途和必要的流程上下文；跨用途、跨账号、跨邮箱或跨流程提交必须拒绝。
7. 验证码仅以安全哈希或等效不可逆验证材料保存，验证与消费必须原子执行；不得记录或返回验证码明文。
8. 同一邮箱、同一用途重发验证码时，服务端必须在签发新验证码的同一原子操作中立即作废此前尚未消费的验证码；仅最新一枚验证码可被验证。

## 备选方案

### 各功能自行设置验证码规则

拒绝。用户体验不一致，且会遗漏部分入口的防暴力破解与限流保护。

### 长期有效或不限次数验证

拒绝。会扩大验证码猜测和泄露后的可利用窗口。

### 只限制发送，不限制验证

拒绝。攻击者仍可对已经签发的验证码进行高频猜测。

### 仅按用途分别限制每日发送量

拒绝。攻击者可通过切换登录、绑定、重置等用途绕开邮件轰炸防护；一期以同一邮箱跨用途的每日总量作为统一上限。

### 重发后保留旧验证码至自然过期

拒绝。会产生多个同时有效的验证码，扩大邮件延迟、泄露或重放带来的攻击窗口。

## 后果

- 验证码服务需要以统一挑战模型提供签发、冷却、验证、消费和失效能力，不能在 Controller 内自行生成或校验。
- 邮件发送响应应避免泄露邮箱归属；安全审计应记录用途、结果和限流原因，但不得记录验证码。
- 测试必须覆盖有效期边界、五次失败、发送冷却、邮箱每日十次总量、邮箱/IP 限流、用途隔离、`Asia/Shanghai` 日界和并发消费。
- 重发与旧挑战作废必须具备原子性；并发重发后只能存在一枚可验证的最新验证码。
