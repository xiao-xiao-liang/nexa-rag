# ADR：一期新账号自动归属内建默认租户

## 状态

已接受。

## 背景

NexaRAG 一期的授权按账号与租户归属隔离，项目当前存在内建默认租户及其默认知识库。真实账号创建后必须有明确租户归属，否则无法为知识库、文档、检索和后续共享能力确定服务端访问范围。

## 决策

1. 通过第三方首次登录补全账号名创建的每个新账号，均自动归属系统内建默认租户；其他账号创建入口若在未来新增，必须遵循同一归属规则。
2. 账号创建、默认租户归属建立、首次第三方身份绑定和登录流程必须具备一致性；创建失败不得留下无归属账号或孤立身份绑定。
3. 登录后的初始当前 `tenantId` 为账号的默认租户；用户切换企业工作空间时，服务端须先校验有效成员资格，再更新该会话的当前租户上下文。
4. 系统须建立持久化租户主数据表；管理员可通过后续受控管理能力创建新的企业租户。多租户成员关系、邀请加入、租户切换和跨租户账号访问的具体规则仍须单独建模。

## 备选方案

### 新账号不分配租户

拒绝。业务数据无法获得可靠的租户隔离和默认知识库访问范围。

### 由客户端在注册或登录时指定租户

拒绝。客户端参数不能作为授权事实来源，且当前没有成员资格校验模型。

### 首期即实现完整租户创建、成员邀请与切换

拒绝。管理员创建企业租户是当前明确需求，但成员关系、角色权限与切换规则尚未定义，不能随创建动作一并臆造。

## 后果

- 身份数据模型需要表达账号与默认租户的归属关系，并由认证上下文同时提供 `accountId` 与 `tenantId`。
- 现有固定用户身份的业务数据需要有明确迁移/兼容策略，避免真实账号上线后出现无归属记录。
- 后续为企业租户加入成员时，应新增成员关系和当前租户选择机制，不得改变本期账号 ID 的稳定性。
