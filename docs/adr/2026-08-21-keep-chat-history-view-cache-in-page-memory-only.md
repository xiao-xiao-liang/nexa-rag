# ADR：历史展示缓存仅保留在页面内存

## 背景

切换已访问会话时，前端可以复用已加载的最近消息页，避免先显示加载态再等待网络请求。若把完整历史写入 LocalStorage、IndexedDB 等持久化浏览器存储，刷新后虽可继续复用，但会扩大用户聊天内容在设备上的留存范围，并增加版本迁移、失效和多账号切换处理。

## 决策

会话历史展示缓存仅存在于当前页面的内存中。页面刷新、关闭或重新打开应用后，缓存自动丢失，历史数据重新由服务端接口读取。不得将消息正文、工具操作快照或历史页写入浏览器持久化存储。

缓存采用 LRU 策略，最多保留 20 个已访问会话的全部已加载历史页；超过上限时淘汰最久未访问会话的缓存。

## 备选方案

1. 将历史页持久化到 LocalStorage 或 IndexedDB。
2. 不保留任何前端历史缓存，每次切换都请求接口。
3. 使用 Service Worker 或离线数据库缓存完整聊天历史。

## 理由

内存缓存足以优化本次页面会话中的重复切换，不改变 MySQL 作为唯一事实源，也避免聊天内容在用户设备上长期留存及由此带来的失效复杂度。

## 后果

- 前端需在会话切换、历史分页和新消息终态时维护内存缓存一致性。
- 刷新后首个会话打开仍可能出现网络加载态，这是预期行为。
- 缓存上限为 20 个会话；超过上限时须正确淘汰最久未访问会话，避免长时间浏览大量会话造成页面内存无界增长。
