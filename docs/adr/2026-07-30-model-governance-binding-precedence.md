# ADR：模型治理配置的绑定优先级

## 背景

系统同时支持模型配置级治理和路由级治理。一次模型调用会经过业务路由，并最终选择一个模型配置，因此可能同时命中两个已保存的治理配置。

当前运行时由全局 `bindingMode` 只选择其中一种，无法让路由配置成为对模型配置的局部覆盖。

## 决策

运行时先查询路由级治理配置；存在时优先使用路由级配置。若路由级配置不存在，再查询并使用最终选中模型配置的治理配置。路由级配置存在但 `enabled = false` 时，表示该路由显式关闭全部治理，不再回退模型配置级。两级配置均不存在时，关闭治理能力。

模型配置级和路由级治理配置可同时存在；每个绑定目标至多有一条未删除的治理配置。

## 备选方案

1. 由全局配置固定只启用一种绑定模式。
2. 前端保存时强制模型配置级和路由级二选一。
3. 模型配置级优先，路由级仅在模型配置级缺失时生效。

## 理由

模型配置级策略提供通用基线，路由级策略能够针对特定任务覆盖基线。路由级优先符合“更具体的配置覆盖更通用的配置”的预期，也无需复制整套模型配置策略。

## 后果

- 运行时解析器需要按路由级、模型配置级的顺序查询。
- 路由级已关闭配置是显式负向覆盖，不能当作缺失配置继续回退。
- 路由级治理配置通过 `GET`、`PUT /api/model/routes/{routeId}/governance` 管理，服务端按 `routeId` 获取 `routeKey`；请求体不包含绑定身份字段。
- 数据库需要保障每个 CONFIG 目标和每个 ROUTE 目标分别至多一条有效配置。
