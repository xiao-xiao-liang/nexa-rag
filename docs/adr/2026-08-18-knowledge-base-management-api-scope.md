# ADR：首期提供知识库管理与按库文档操作接口

## 状态

已接受。

## 背景

新增知识库实体后，调用方需要在当前租户范围内管理知识库，并在目标知识库中查看、上传和管理文档。仅增加数据表或在现有文档接口中附加字段，无法形成可用且受边界约束的知识库能力。

## 决策

1. 首期提供知识库的创建、分页列表、详情、名称/描述更新和删除接口。
2. 文档分页查询与上传入口必须明确目标知识库；文档详情、处理、重试、删除和分块读取必须验证文档归属的知识库与当前租户。
3. 知识库列表与详情返回仅提供已确认的基础管理字段和文档统计所需的服务端事实；不伪造成员、权限、跨库检索或前端聚合数据。
4. 成员授权、组织内共享策略、跨知识库检索策略和知识库级处理/索引配置不进入本期接口范围。

## 备选方案

### 只扩展现有全局文档列表的 `knowledgeBaseId` 筛选参数

拒绝。调用方无法创建、识别或维护知识库，也无法验证该标识属于当前租户。

### 首期一并实现组织成员与共享权限管理

暂不采用。认证与组织授权将由后续 Sa-Token `auth` 模块单独定义，避免在当前阶段凭空设计角色模型。

## 后果

- 新旧文档接口需要演进为以知识库为入口或显式携带知识库上下文，并保留清晰的兼容策略。
- 所有写操作都需要先校验目标知识库属于当前租户，再执行文档或知识库业务。
- 删除知识库的文档处理和索引清理语义需要单独确定。
