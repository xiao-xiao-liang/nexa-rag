# ADR：第三方身份全局唯一绑定且不支持跨账号迁移

## 状态

已接受。

## 背景

NexaRAG 允许账号绑定多个第三方身份。若同一 QQ、飞书、Google 或 GitHub 身份能同时绑定多个账号，或由另一个账号直接迁移取得，则该外部身份的归属不再确定，并可能导致账户接管。

## 决策

1. 以“提供方标识 + 服务端验证得到的外部主体标识”作为第三方身份的全局唯一键。
2. 同一第三方身份在全系统中最多绑定一个 NexaRAG 账号。
3. 当当前账号尝试绑定已归属其他账号的第三方身份时，服务端必须拒绝请求；不得自动解绑、覆盖或迁移原绑定。
4. 解绑后，该第三方身份才可在新的完成认证流程中绑定到其他账号，且仍受最后凭据保护约束。

## 备选方案

### 同一第三方身份绑定多个账号

拒绝。会使第三方认证无法唯一确定 NexaRAG 登录主体。

### 新账号绑定时自动迁移原绑定

拒绝。当前登录会话无法证明操作者对原账号拥有足够控制权，存在账户接管风险。

### 由管理员或客服手动迁移绑定

本期不纳入范围。若未来需要，必须另行定义原账号验证、审计、冷却期和申诉流程，不能复用普通绑定接口。

## 后果

- 数据库必须以提供方和外部主体标识建立唯一约束，并将重复键冲突映射为明确的业务错误。
- 绑定动作必须在完成服务端第三方认证后执行，不能信任客户端传入的第三方用户标识。
- 用户界面需提示该第三方身份已被其他账号绑定，但不得泄露原账号的任何信息。
