# ADR：首期维持文档级处理与索引配置

## 状态

已接受。

## 背景

当前文档上传、外部导入与处理请求可以携带解析、切分和索引配置，并将实际配置保存为文档处理快照。新增知识库时，若同时增加知识库级默认配置，需要定义默认值与文档显式值的优先级、已处理文档是否重跑、配置变更的版本与索引重建规则。

## 决策

1. 首期知识库不保存解析、切分、向量索引或关键词索引的默认配置字段。
2. 每份文档继续在创建、上传或处理时确定配置，并以 `processConfigJson` 作为该文档的处理快照。
3. 知识库的创建、更新或重命名不得改变任何已存在文档的处理配置或触发重新处理。
4. 知识库级默认配置作为未来独立能力设计，届时需定义继承、覆盖、版本、重处理和索引重建语义。

## 备选方案

### 立即将现有配置迁移到知识库级

拒绝。会丢失不同文档使用不同处理策略的能力，并使历史处理结果的配置来源不清。

### 知识库与文档同时保存配置，但不定义优先级

拒绝。调用方无法预测实际生效配置，后续排障和重试会不可追溯。

## 后果

- 知识库表保持精简，不承载与当前文档处理流水线无关的配置字段。
- 嵌套文档接口仍复用既有处理配置 DTO；目标知识库只决定归属和检索范围。
- 将来增加知识库级默认配置时，需要提供明确的“仅影响新文档”或“创建重处理任务”的迁移策略。
