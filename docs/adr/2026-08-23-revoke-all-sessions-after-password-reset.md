# ADR：密码重置后撤销账号全部既有登录会话

## 状态

已接受。

## 背景

本地密码重置常用于忘记密码或凭据疑似泄露的场景。若重置密码后仍保留全部既有 Sa-Token 会话，持有旧 Token 的设备或攻击者仍可继续访问账号。

## 决策

1. 成功重置本地密码后，服务端必须撤销该账号全部既有 Sa-Token 登录会话，包括发起重置操作的既有会话。
2. 密码哈希更新和账号级会话撤销必须作为同一安全操作完成，不能因撤销失败而保留旧会话。
3. 重置完成后不得自动建立新的 Sa-Token 登录态；用户必须通过新密码、当前已验证邮箱验证码或已绑定第三方身份重新登录。
4. 其他设备以及发起重置的当前设备再次访问时均必须重新登录。

## 备选方案

### 保留所有既有会话

拒绝。无法阻断已泄露 Token 的持续访问。

### 只注销当前会话

拒绝。不能保护其他可能被盗用的设备会话，且与密码重置的止损目的冲突。

### 仅由客户端删除本地 Token

拒绝。服务端无法撤销其他设备或恶意客户端持有的凭据。

### 重置成功后自动登录

拒绝。密码找回与登录态建立保持分离，避免重置流程额外承载会话签发及其潜在的会话固定风险；用户可使用新密码或无密码邮箱验证码显式登录。

## 后果

- Sa-Token 配置与封装需要支持按 `accountId` 撤销所有 Token 和会话，并可验证旧 Token 已失效。
- 密码重置后的前端应提示所有设备均需重新登录，并跳转到登录入口；不得在本地继续使用旧 Token 或假定存在新的自动登录会话。
- 设置密码、已登录修改密码、邮箱更换和第三方绑定变更是否触发同等范围的会话撤销，仍需分别确认。
