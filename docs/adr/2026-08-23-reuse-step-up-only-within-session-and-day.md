# ADR：敏感操作使用当前会话的十五分钟最近验证授权

## 状态

已接受。

## 背景

第三方身份变更、密码设置或修改、设备会话撤销均会影响账号登录入口或既有会话。若每次操作都要求验证，会给用户连续完成安全设置带来不必要摩擦；若授权跨会话或按自然日长期有效，则会扩大被盗会话或遗留授权的风险。

## 决策

1. 二次验证成功，或当前已验证邮箱的一次性验证码、QQ、飞书、Google、GitHub 登录成功，或邮箱自助注册成功后，服务端签发“最近验证授权”；它仅绑定完成验证的 `accountId` 和当前 Sa-Token 会话标识，有效期为 15 分钟。账号名/邮箱密码登录只建立普通登录态，不自动签发该授权。
2. 在有效期内，该授权可复用于第三方身份绑定/解绑、首次设置或修改本地密码、指定设备下线和退出所有设备。
3. 授权及其有效期必须完全由服务端保存和校验，前端不得以“已验证”标记替代；每一项具体敏感操作仍应使用用途绑定、短期且单次消费的操作挑战防重放。
4. 新建 Sa-Token 会话不能复用旧会话的最近验证授权；登出、会话被撤销、账号级会话撤销、授权到期或服务端判定风险事件后，授权必须立即无效。
5. 更换邮箱始终需要旧邮箱和新邮箱各自独立验证，最近验证授权不能替代任何一方；密码重置继续走独立找回流程并在成功后撤销全部既有会话。

## 备选方案

### 在账号级别按自然日复用

拒绝。新设备或新登录可复用旧会话的授权，扩大跨设备会话被盗用时的风险，也让一次验证形成全天高权限通行证。

### 在同一会话内永久复用

拒绝。三天滑动登录态可能长期有效，不能使高风险凭据变更授权无限延续。

### 每次敏感操作都重新验证

拒绝。用户连续完成绑定、密码设置和设备管理时会反复收码或输入密码，体验不必要地受损。

### 所有登录方式都自动签发最近验证授权

拒绝。用户明确仅将邮箱验证码和第三方登录视作可自动获得最近验证授权的方式；账号名/邮箱密码登录后仍须通过当前密码或邮箱验证码完成二次验证。

## 后果

- 服务端须以 `accountId`、当前会话标识、签发和到期时间保存并校验授权状态；不得只在前端保存“已验证”标记。
- 风险事件的首期最小实现至少包括：新建会话、登出、会话撤销和密码重置；后续可增加基于异常 IP 或设备变化的风控撤销。
- 敏感操作接口和前端需要能够识别授权缺失或过期，并引导用户完成一次新的二次验证。
- 15 分钟有效期、Redis 过期时间和测试时钟须使用服务端时间计算，不能依赖客户端时间。
