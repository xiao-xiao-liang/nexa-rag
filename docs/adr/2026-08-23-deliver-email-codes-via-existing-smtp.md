# ADR：认证邮件复用现有 SMTP 配置投递

## 状态

已接受。

## 背景

邮箱验证码登录、注册、密码管理、邮箱变更和安全操作通知均依赖邮件投递。项目已具备 SMTP 配置，一期无需再引入专有邮件服务商 SDK 或额外的消息投递依赖。

## 决策

1. 一期邮箱验证码和安全操作通知统一通过项目现有 SMTP 配置发送。
2. 开发和集成环境可将 SMTP 配置指向 Mailpit 或其他测试 SMTP；生产环境通过部署环境配置注入真实 SMTP 服务地址与凭据。
3. SMTP 密码、授权码和其他敏感配置不得提交到仓库、写入日志、返回接口或暴露给前端。
4. 验证码邮件只包含验证码、用途、有效期和安全提示；安全通知邮件只包含脱敏事件信息和处理指引。两者均不得包含密码、Sa-Token、Cookie、完整账号安全信息或可直接执行敏感操作的链接。
5. SMTP 发送失败时不得签发可被验证的验证码挑战；对外响应应避免泄露邮箱或账号是否存在，内部记录可观测的失败原因与用途。

## 备选方案

### 接入专有邮件服务商 SDK

拒绝。一期现有 SMTP 能力已经满足验证码投递需求；引入额外 SDK 会增加供应商耦合、凭据管理和维护成本。

### 开发环境直接打印验证码或返回给前端

拒绝。会使测试路径与生产安全模型不一致，并可能将验证码暴露在日志、浏览器或接口响应中；开发环境应使用测试 SMTP 收件箱验证投递。

## 后果

- 认证邮件服务需封装为统一投递能力，业务 Controller 不得直接拼装或发送邮件。
- 部署文档需要列出 SMTP 主机、端口、发送方、认证方式和凭据注入方式，但不得记录真实凭据。
- 集成测试可使用测试 SMTP 验证邮件投递与挑战状态的一致性；邮件发送失败、超时与重试策略须在实现设计中明确。
