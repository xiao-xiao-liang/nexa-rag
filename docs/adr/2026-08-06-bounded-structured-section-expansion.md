# ADR：标题命中采用有限后代正文扩展

## 背景

当前 Markdown 切分会产生仅含标题的片段。此类片段可能在向量检索中排名靠前，却不足以回答用户问题；其下的正文又可能因相似度阈值、候选数量或排序限制未进入最终上下文。

将整章的所有子节直接加入上下文虽然能提高覆盖率，但会显著增加 Token 成本并引入无关证据。仅返回标题或按文档顺序盲目补相邻片段，则无法保证答案相关性。

## 决策

结构化章节检索只适用于可识别标题层级的 Word、PDF 和 Markdown 文档；Excel 与纯文本继续使用各自既有的按表格、行或窗口的切分策略，不构造虚假的章节关系。

对于结构化章节文档：

1. 纯标题片段不作为最终回答证据。
2. 当候选命中上级标题或结构节点时，只在该节点的后代正文片段范围内，使用本轮检索问题进行二次排序。
3. 二次排序最多补充 2 至 3 个最相关正文片段；实际数量还受最终上下文 Token 预算限制。
4. 若有限扩展后仍无足以支持回答的正文，系统保持“资料不足”的拒答语义。
5. 若解析产物缺失可用标题层级或层级异常，系统退回窗口切块并正常索引，标记为非结构化降级且不执行章节后代扩展。
6. 向量候选数量、粗过滤阈值、BM25 候选数量、RRF 截断深度、Rerank 候选上限、最终接受阈值和扩召触发条件不针对单个案例硬编码；它们应以运行配置管理，后续由独立的 RAGAS 评测系统校准。
7. 最终证据低置信或不完整时，采用保守拒答；系统不得基于部分证据输出猜测性答案。

本期不建设评测平台或预设固定 P95 延迟门槛；仅保留链路日志和回归测试。后续评测系统应联合检索召回、排序质量、最终证据覆盖率、P50/P95 延迟、Rerank 成本、扩召触发率和扩召成功率，以帕累托最优组合指导运行配置。

## 备选方案

1. 命中标题后把整个章节的所有子节加入上下文。
2. 不做结构扩展，只依赖向量相似度、关键词检索和 Rerank。
3. 按 `chunkOrder` 固定追加命中片段后的 1 至 3 个相邻片段。

## 理由

有限后代扩展将标题作为结构定位信号，而不是事实证据；它在相关性、Token 成本和实现可控性之间取得平衡。二次排序限定在后代正文范围内，避免整章注入和顺序邻接带来的大量噪声。

## 后果

- 文档模型必须能区分标题层级关系与超长文本的窗口父子关系。
- 检索工作流需要识别标题/结构候选，并支持受范围约束的二次排序和 Token 预算截断。
- 存量文档需要在结构化切分与索引能力完成后重新处理，才能稳定提供该语义；本次迁移采用全量索引重建，不保留旧向量索引的并行服务能力。
- 本期回归测试必须覆盖“命中上级标题、答案位于子节正文”的查询；有限扩展的召回收益与延迟成本由后续评测系统系统化度量。
